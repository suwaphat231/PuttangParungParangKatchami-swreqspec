# Test Cases: ส่งผลการปฏิบัติงาน (UC-12)

## ขอบเขตและหลักฐาน

- Test Cases นี้อ้างอิง `spec.md` (FR-RES-01 ถึง FR-RES-03, AC-RES-01 ถึง AC-RES-03, Constraints, NFR-REL-01 และ NFR-AUD-01) และ Scenarios ใน `tasks.md` (T-06)
- Test Function Name ใช้ snake_case เป็นชื่อที่เสนอสำหรับการทดสอบเมื่อมี implementation และ test harness; Repository ไม่มี Source/Backend ของ UC-12 หรือ Test Framework ที่ตรวจพบ
- Tool ระบุวิธีทดสอบตามสิ่งที่มีจริง: ตรวจเอกสาร/Prototype ด้วยมือเพื่อสาธิตเท่านั้น และต้องทดสอบกับระบบจริงเมื่อมี implementation
- ทุกเคสมีสถานะ `ร่าง` เพราะยังไม่ได้ Execute
- ไม่กำหนดฟิลด์ประเมิน วิธีระบุสิทธิ์ รูปแบบเวลา กลไก transaction หรือข้อความแจ้งเตือนที่เอกสารไม่ได้ระบุ; Q-01 เรื่องผู้มีสิทธิ์ปลดล็อกยังเปิดอยู่

## ข้อจำกัดและ Implementation Gap

- **Implementation Gap:** ไม่พบ Source/Backend หรือระบบจริงสำหรับ UC-12 ใน tracked files ของ Repository; การยืนยันส่งผล, การจัดเก็บถาวร, การตรวจสิทธิ์ และ transaction จริงจึงยังทดสอบไม่ได้
- **Prototype:** `prototype.html` ใช้ข้อมูลบุคคลและสถานการณ์จำลองในหน้าเว็บ; ใช้ `localStorage` จำลองสถานะ/ผู้ส่ง/เวลา และมีทางจำลองการบันทึกล้มเหลว การแสดงผลเหล่านี้ไม่ยืนยันการบันทึกถาวรบน Backend, Atomic Transaction, ผู้ใช้งานจริง หรือ Audit Log จริง
- **Test Framework:** ไม่พบไฟล์ Test แยกหรือ configuration ของ Test Framework; Test Function Name เป็นชื่อเสนอ ไม่ใช่ฟังก์ชันที่มีอยู่หรือรันแล้ว
- **Open Question:** Q-01 เรื่องผู้มีสิทธิ์ปลดล็อกผลหลังส่งยังต้องยืนยันกับเจ้าหน้าที่; เคสสิทธิ์จึงจำกัดการตรวจว่าผู้ไม่มีสิทธิ์แก้ไขไม่ได้ โดยไม่ระบุบทบาทผู้มีสิทธิ์ขึ้นเอง
- **สถานะการ Execute:** Test Cases ทั้งหมด 8 รายการยังเป็น `ร่าง`; ไม่มีผลการรันทดสอบจริง
