# Implementation Plan: ดูประกาศรับสมัคร

Spec: `SPEC-02-02`  
Source: UC-02  
Status: Draft  
Updated: 2569-09-19

## Objective
พัฒนาหน้าสำหรับนักศึกษาที่เข้าสู่ระบบเพื่อค้นหาและดูรายละเอียดประกาศรับสมัคร Lab Boy ที่เผยแพร่และยังเปิดรับสมัครอยู่

## Scope
- ตรวจสอบ session ก่อนเข้าถึงหน้า
- แสดงเฉพาะประกาศที่เผยแพร่และสถานะ `เปิดรับสมัคร`
- ค้นหา/กรองด้วยวิชาและภาคการศึกษา
- แสดงคุณสมบัติ ช่วงเวลารับสมัคร และจำนวนที่รับ
- แสดงสถานะประกาศที่เกี่ยวข้อง ได้แก่ `เปิดรับสมัคร`, `เต็ม`, `ปิดรับสมัคร`
- ไม่รวมขั้นตอนสมัครเป็น Lab Boy ซึ่งอยู่ใน UC-01

## Design Decisions
- ผู้ใช้ต้องเข้าสู่ระบบก่อนดูรายการและรายละเอียดประกาศ
- รายการหลักแสดงเฉพาะประกาศที่เผยแพร่และยัง `เปิดรับสมัคร`
- ประกาศที่ `เต็ม` หรือ `ปิดรับสมัคร` ไม่แสดงในรายการของ UC-02
- การค้นหาใช้วิชาและภาคการศึกษาเป็นตัวกรอง
- เวลาเป้าหมายการตอบสนองของรายการและรายละเอียดคือไม่เกิน 2 วินาทีที่ p95
- ข้อมูลประกาศต้องมาจากประกาศที่เจ้าหน้าที่หรืออาจารย์เผยแพร่แล้ว

## Work Plan

### 1. Announcement Data and Status Rules
- [ ] กำหนดข้อมูลประกาศที่ใช้แสดง: วิชา ภาคการศึกษา คุณสมบัติ ช่วงเวลารับสมัคร จำนวนที่รับ และสถานะ
- [ ] กำหนดเงื่อนไขว่าเฉพาะประกาศที่เผยแพร่เท่านั้นจึงจะแสดง
- [ ] กำหนดการคำนวณสถานะ `เปิดรับสมัคร`, `เต็ม`, `ปิดรับสมัคร`
- [ ] ใช้เวลาและช่วงรับสมัครตาม timezone `Asia/Bangkok`
- [ ] ไม่เปิดเผยฉบับร่างหรือประกาศที่ยังไม่ได้เผยแพร่

### 2. Authentication and Authorization
- [ ] ตรวจสอบ session ก่อนเรียกข้อมูลรายการประกาศ
- [ ] ส่งผู้ใช้ที่ยังไม่เข้าสู่ระบบไปยังหน้าเข้าสู่ระบบหรือแสดงข้อผิดพลาดที่กำหนด
- [ ] ตรวจสอบว่าข้อมูลที่แสดงเป็นข้อมูลประกาศที่เผยแพร่ต่อผู้ใช้ได้

### 3. List and Search Flow
- [ ] สร้าง API/query สำหรับรายการประกาศที่กรอง `เผยแพร่` และ `เปิดรับสมัคร`
- [ ] รองรับการค้นหา/กรองด้วยวิชา
- [ ] รองรับการค้นหา/กรองด้วยภาคการศึกษา
- [ ] กำหนดพฤติกรรมเมื่อไม่พบรายการให้ชัดเจน
- [ ] รองรับ pagination หรือกลไกจำกัดผลลัพธ์หากจำนวนประกาศมาก
- [ ] แสดงสถานะและข้อมูลสำคัญในรายการให้อ่านและเปรียบเทียบได้ง่าย

### 4. Announcement Detail Flow
- [ ] เปิดรายละเอียดจากประกาศที่ผู้ใช้เลือก
- [ ] แสดงคุณสมบัติ ช่วงเวลารับสมัคร และจำนวนที่รับครบถ้วน
- [ ] แสดงสถานะประกาศปัจจุบัน
- [ ] ป้องกันการเปิดดูประกาศที่ไม่เผยแพร่หรือไม่มีสิทธิ์เข้าถึง
- [ ] หากสถานะเปลี่ยนเป็น `เต็ม` หรือ `ปิดรับสมัคร` ให้แสดงสถานะล่าสุดและไม่แสดงเป็นรายการสมัครได้

### 5. Performance and Reliability
- [ ] เพิ่ม index สำหรับสถานะการเผยแพร่ วิชา ภาคการศึกษา และช่วงเวลารับสมัครตามความเหมาะสม
- [ ] ทดสอบเวลาตอบสนองรายการและรายละเอียดที่ p95 ไม่เกิน 2 วินาที
- [ ] กำหนด loading, empty, timeout และ error state
- [ ] ตรวจสอบว่าข้อมูลสถานะไม่ค้างจาก cache จนแสดงว่าเปิดรับสมัครผิดจริง

## Test Plan

### Functional Tests
- [ ] ผู้ใช้ที่เข้าสู่ระบบเห็นเฉพาะประกาศที่เผยแพร่และเปิดรับสมัคร (AC-ANN-01)
- [ ] ผู้ใช้ค้นหา/กรองประกาศด้วยวิชาและภาคการศึกษาได้
- [ ] การเลือกประกาศแสดงคุณสมบัติ ช่วงเวลา และจำนวนที่รับครบถ้วน (AC-ANN-02)
- [ ] ประกาศที่เต็มหรือปิดรับสมัครไม่แสดงในรายการสมัครได้
- [ ] สถานะแสดงเป็น `เปิดรับสมัคร`, `เต็ม` หรือ `ปิดรับสมัคร` ตามข้อมูลล่าสุด (AC-ANN-03)
- [ ] ผู้ใช้ที่ยังไม่เข้าสู่ระบบไม่สามารถเข้าถึงหน้าประกาศได้
- [ ] เมื่อไม่พบประกาศ ระบบแสดง empty state ที่เข้าใจได้

### Performance and Security Tests
- [ ] รายการประกาศตอบสนองไม่เกิน 2 วินาทีที่ p95 (NFR-PERF-01)
- [ ] รายละเอียดประกาศตอบสนองไม่เกิน 2 วินาทีที่ p95 (NFR-PERF-01)
- [ ] ผู้ใช้ไม่สามารถดูข้อมูลฉบับร่างหรือประกาศที่ไม่เผยแพร่
- [ ] คำค้นและตัวกรองไม่ทำให้เกิดการเข้าถึงข้อมูลนอกขอบเขต
- [ ] รายละเอียดสำคัญอ่านและค้นหาได้ง่ายตาม NFR-USE-01

## Dependencies
- ระบบ authentication/session
- ข้อมูลรายวิชาและภาคการศึกษา
- ข้อมูลประกาศที่สร้างและเผยแพร่โดยเจ้าหน้าที่/อาจารย์
- กติกาคำนวณช่วงเวลาและจำนวนที่รับ
- ฐานข้อมูลและกลไกค้นหา/กรอง

## Open Items
- [ ] ยืนยันว่าประกาศ `เต็ม` หรือ `ปิดรับสมัคร` ต้องถูกซ่อนจากรายการ UC-02 ตามข้อสรุปนี้
- [ ] ยืนยันข้อความและพฤติกรรมเมื่อผู้ใช้ยังไม่เข้าสู่ระบบ
- [ ] ยืนยันว่ารายการต้องมี pagination และจำนวนรายการต่อหน้าเท่าใด
- [ ] ยืนยันรูปแบบการแสดงวันเวลาและภาคการศึกษา
- [ ] ยืนยันว่าปุ่มไปสมัครจากรายละเอียดจะเชื่อมไป UC-01 หรือไม่
