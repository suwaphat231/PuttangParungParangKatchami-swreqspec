# Feature: จัดทำตารางปฏิบัติงาน
Spec ID: SPEC-09-09- | Source: Use Case Diagram UC-09 | Use case: UC-09
Owner: ทีม A | Status: Draft v2 | Updated: 2569-09-19

## Goal
อาจารย์จัดสรรวันและช่วงเวลาปฏิบัติงานให้ Lab Boy ตามโควตาและเงื่อนไขของระบบ

## Scope
### In scope
- เลือกผู้ปฏิบัติงาน
- ดูวันและช่วงเวลาที่ใช้ได้
- กำหนดตาราง
- ตรวจสอบความซ้ำซ้อน
- บันทึกตาราง
### Out of scope
- ตรวจสอบวันและเวลาปฏิบัติงาน (UC-19)
- ติดตามและตรวจสอบการจ่ายเงิน (UC-16)

## Constraints
- ห้ามจัดตารางซ้อนกันสำหรับ Lab Boy คนเดียวกัน โดยถือว่าซ้อนกันเมื่อช่วงเวลาใหม่ทับกับช่วงเวลาเดิมแม้เพียงบางส่วน
- ต้องไม่เกินโควตาของแต่ละช่วงเวลา
- อนุญาตให้แก้ไขตารางได้ก่อนถึงเวลาเริ่มปฏิบัติงานเท่านั้น หลังถึงเวลาเริ่มปฏิบัติงานแล้วห้ามแก้ไข

## Requirements
- FR-SCH-01 ระบบต้องแสดงช่วงเวลาที่สามารถจัดตารางได้    <- UC-09 requirement 1
- FR-SCH-02 ระบบต้องตรวจสอบว่าโควตาของช่วงเวลานั้นเหลือมากกว่า 0 ก่อนบันทึก หากโควตาเต็มต้องปฏิเสธการบันทึกและแจ้งว่าโควตาเต็ม    <- UC-09 requirement 2
- FR-SCH-03 ระบบต้องตรวจสอบตารางเดิมของ Lab Boy คนเดียวกันและช่วงเวลาที่เกี่ยวข้องก่อนบันทึก เพื่อป้องกันการจัดตารางซ้ำ    <- UC-09 requirement 3
- FR-SCH-04 เมื่อบันทึกสำเร็จต้องแสดงตารางล่าสุด    <- UC-09 requirement 4

## Quality Requirements
- NFR-REL-01 การตรวจสอบและตัดโควตาต้องทำแบบ Atomic Transaction เพื่อป้องกันโควตาติดลบหรือเกินจำนวนที่กำหนดเมื่อมีผู้ใช้หลายคนบันทึกพร้อมกัน
- NFR-PERF-01 การตรวจสอบโควตาและตารางซ้ำซ้อนต้องตอบสนองภายใน 2 วินาทีใน 95% ของคำขอ ภายใต้การใช้งานปกติ

## Acceptance Criteria
- [ ] AC-SCH-01 (FR-SCH-02)
      Given ช่วงเวลามีโควตาเหลือ 1
            When  จัดตารางให้ 1 คน
            Then  บันทึกสำเร็จและโควตาเหลือ 0
      Given ช่วงเวลาไม่มีโควตาเหลือ
            When  จัดตารางและบันทึก
            Then  ระบบปฏิเสธการบันทึกและแจ้งว่าโควตาเต็ม
- [ ] AC-SCH-02 (FR-SCH-03)
      Given Lab Boy คนเดียวกันมีตารางเดิม 09:00–12:00
            When  บันทึกตารางใหม่เวลา 11:00–14:00
            Then  ระบบปฏิเสธการบันทึกและแสดงรายการที่ขัดแย้ง
- [ ] AC-SCH-03 (NFR-REL-01)
      Given มีผู้ใช้หลายคนบันทึกตารางในช่วงเวลาเดียวกัน
            When  ระบบตรวจสอบและตัดโควตา
            Then  การตัดโควตาต้องเป็น Atomic Transaction และโควตาต้องไม่ติดลบหรือเกินจำนวนที่กำหนด

## Assumptions & Open Questions
- ASM-01 โควตาต่อช่วงเวลามีแหล่งข้อมูลที่เชื่อถือได้
- ASM-02 อนุญาตให้แก้ไขตารางได้ก่อนถึงเวลาเริ่มปฏิบัติงานเท่านั้น และห้ามแก้ไขเมื่อถึงเวลาเริ่มปฏิบัติงานแล้ว
- ASM-03 โควตาของช่วงเวลาถือว่าใช้ได้เมื่อมีค่าคงเหลือมากกว่า 0 และข้อความปฏิเสธเมื่อเต็มคือ “โควตาเต็ม”
- ASM-04 การตรวจตารางซ้ำซ้อนพิจารณาเฉพาะ Lab Boy คนเดียวกันและช่วงเวลาที่เกี่ยวข้อง
- ASM-05 ช่วงเวลาถือว่าซ้อนกันเมื่อช่วงเวลาใหม่ทับกับช่วงเวลาเดิมแม้เพียงบางส่วน
- ASM-06 การตรวจสอบและตัดโควตาเมื่อมีการบันทึกพร้อมกันใช้ Atomic Transaction
- ASM-07 เป้าหมายประสิทธิภาพของการตรวจสอบโควตาและตารางซ้ำซ้อนคือไม่เกิน 2 วินาทีใน 95% ของคำขอภายใต้การใช้งานปกติ
- Q-01 [ปิดประเด็น] อนุญาตให้เปลี่ยนตารางหลังประกาศได้ก่อนถึงเวลาเริ่มปฏิบัติงานเท่านั้น
- Q-02 ใครเป็นผู้กำหนดวันและช่วงเวลาที่สามารถจัดตารางได้ และช่วงเวลาเหล่านั้นมาจากแหล่งข้อมูลใด?
- Q-03 ใครมีสิทธิ์สร้าง แก้ไข หรือลบตารางปฏิบัติงาน?
- Q-04 เมื่อบันทึกสำเร็จต้องแสดงเฉพาะตารางล่าสุดของผู้ปฏิบัติงาน หรือต้องแสดงตารางทั้งหมดของประกาศหรือรอบรับสมัคร?
- Q-05 ระบบต้องรองรับการลบหรือยกเลิกตารางที่บันทึกแล้วหรือไม่ และหากรองรับต้องคืนโควตาหรือไม่?
