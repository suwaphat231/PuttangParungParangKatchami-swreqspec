# Plan: จัดการระบบ (v2)

## วัตถุประสงค์
ปรับปรุงเอกสารข้อกำหนดความต้องการ (software requirements specification) ให้มีความชัดเจนและสอดคล้องกัน โดยเฉพาะเรื่องบทบาทของผู้ใช้งาน การอนุมัติค่าตั้งค่าสำคัญ และการบันทึกประวัติการเปลี่ยนแปลง

## ขอบเขตงาน
- ตรวจสอบความสอดคล้องของบทบาทในเอกสาร
- กำหนดบทบาทที่ใช้ในระบบให้เป็นชุดเดียวกัน: นักศึกษา, อาจารย์, เจ้าหน้าที่, System Owner
- ปรับกระบวนการอนุมัติค่าตั้งค่าสำคัญให้ชัดเจนว่าต้องอยู่ในสถานะ Pending Approval ก่อนมีผลบังคับใช้
- เพิ่มความชัดเจนเรื่อง audit log และสถานะบริการ
- ตรวจสอบ Acceptance Criteria และ Traceability ให้สอดคล้องกับ requirement ที่ปรับแล้ว

## แผนการทำงาน
### 1. ปรับโครงสร้างบทบาท
- กำหนดบทบาทหลักและความรับผิดชอบเริ่มจาก
  - นักศึกษา: ผู้ใช้งานทั่วไป
  - อาจารย์: ผู้อนุมัติการเปลี่ยนแปลงสำคัญ
  - เจ้าหน้าที่: ผู้จัดการระบบ/ผู้ใช้/ค่าตั้งค่าในขอบเขตที่ได้รับมอบหมาย
  - System Owner: ผู้ดูแลระบบระดับสูง

### 2. ปรับตรรกะ approval flow
- ค่าตั้งค่าสำคัญต้องไม่มีผลบังคับใช้ทันที
- ต้องอยู่ในสถานะ Pending Approval
- การอนุมัติต้องไม่ใช่ Self-approval
- อนุมัติได้เฉพาะผู้มีสิทธิ์ตามบทบาทที่กำหนด

### 3. ปรับ NFR และ Audit
- เพิ่มความชัดเจนว่าการเปลี่ยนแปลงสำคัญต้องบันทึกผู้ทำรายการ เวลา และสถานะก่อน/หลัง
- ระบุให้ระบบแสดงสถานะบริการพร้อมเวลาของสถานะล่าสุด

### 4. ตรวจสอบความครบถ้วน
- Requirement และ Acceptance Criteria ต้องครอบคลุมความต้องการที่ปรับแล้ว
- Traceability ต้องชี้ไปยัง AC ที่เกี่ยวข้องอย่างถูกต้อง

## ผลลัพธ์ที่คาดหวัง
- เอกสารสเปคมีความสอดคล้องภายในเอกสารเดียวกัน
- บทบาทและสิทธิ์ชัดเจนและสามารถนำไปสู่การออกแบบระบบต่อได้
- กระบวนการอนุมัติค่าตั้งค่าสำคัญมีความปลอดภัยและตรวจสอบได้
- สามารถใช้เป็นฐานสำหรับการพัฒนาต่อในรอบถัดไป

## สถานะปัจจุบัน
- Completed: ปรับบทบาทและ approval flow ให้สอดคล้องตามข้อกำหนดที่ระบุ
- Completed: ปรับ audit log และ service status requirements
- Completed: ตรวจสอบและปรับคำอธิบายให้เป็นเวอร์ชัน v2
- Commit: ดำเนินการ commit เอกสารปรับปรุงเรียบร้อยแล้ว

## หมายเหตุ
เอกสารนี้จัดทำเพื่อให้การทำงานมีความต่อเนื่อง และสามารถใช้เป็นเอกสารอ้างอิงสำหรับการปรับปรุงหรืออนุมัติต่อในภายหลัง
