# Feature: จัดการระบบ
Spec ID: SPEC-17-17- | Source: Use Case Diagram UC-17 | Use case: UC-17
Owner: ทีม A | Status: Draft v1 | Updated: 2569-09-19

## Goal
ผู้ดูแลระบบจัดการข้อมูลตั้งค่าและรายการระบบที่อนุญาตให้ใช้งานภายในระบบ โดยจัดการสิทธิ์การเข้าถึงฟังก์ชัน การกำหนดค่าตั้งค่าสำคัญ การอนุมัติการเปลี่ยนแปลงสำคัญ และตรวจสอบสถานะบริการ เพื่อให้ระบบทำงานได้ถูกต้อง ปลอดภัย และสามารถตรวจสอบประวัติการเปลี่ยนแปลงได้

## Assumptions
- AS-01 Use Case นี้ครอบคลุมการจัดการผู้ใช้และบทบาท การตั้งค่าและการควบคุมระบบ การตรวจสอบสถานะบริการ และบันทึกประวัติการเปลี่ยนแปลง (audit log) ภายในระบบ
- AS-02 ค่าตั้งค่าสำคัญหมายถึงค่าที่ส่งผลต่อความปลอดภัยหรือการทำงานหลักของระบบ เช่น การเปิด-ปิดฟังก์ชันระดับระบบ การกำหนดสิทธิ์ระดับระบบ หรือค่าที่มีผลต่อการทำงานปกติของบริการ ค่าดังกล่าวต้องได้รับการอนุมัติจาก Super Admin ก่อนมีผลบังคับใช้
- AS-03 ผู้ดูแลระบบมี 3 ระดับสิทธิ์หลัก คือ Admin, Super Admin, และ System Owner โดยแต่ละระดับมีหน้าที่และสิทธิ์ที่ต่างกันตามนโยบายระบบ
- AS-04 Audit log จะบันทึกเฉพาะการเปลี่ยนแปลงที่สำคัญเท่านั้น พร้อมข้อมูลผู้ทำรายการ เวลา และรายละเอียดการเปลี่ยนแปลง
- AS-05 การตรวจสอบสถานะบริการหมายถึงการดูสถานะปัจจุบันและความพร้อมใช้งานของบริการ เช่น Online, Offline, Error, Healthy, Unhealthy

## Scope
### In scope
- จัดการผู้ใช้และบทบาทที่ระบบอนุญาต
- จัดการค่าตั้งระบบที่มีผลต่อการทำงานของระบบ
- จัดการค่าตั้งค่าสำคัญที่ต้องมีการอนุมัติจาก Super Admin ตามนโยบาย
- ตรวจสอบสถานะบริการและความพร้อมใช้งานปัจจุบัน
- บันทึกประวัติการเปลี่ยนแปลงของข้อมูลที่สำคัญ (audit log)
### Out of scope
- อนุมัติสิทธิ์การเข้าใช้งาน (UC-18)
- การกำหนดนโยบายธุรกิจภายนอกระบบที่ไม่ใช่การตั้งค่าในระบบ
- การเริ่ม/หยุด/รีสตาร์ทบริการโดยตรง เว้นแต่จะถูกระบุเป็นส่วนหนึ่งของ Use Case แยกต่างหาก

## Constraints
- เฉพาะผู้ดูแลระบบที่ได้รับสิทธิ์เท่านั้นที่สามารถเข้าถึงเมนูและฟังก์ชันจัดการระบบ
- ระดับสิทธิ์หลักประกอบด้วย Admin, Super Admin, และ System Owner โดย Admin ดู/จัดการค่าตั้งค่าและผู้ใช้ที่ได้รับมอบหมาย, Super Admin อนุมัติการเปลี่ยนแปลงสำคัญตามนโยบายระบบ, และ System Owner ดูแลเกี่ยวกับระบบเป็นหลัก และดู/แก้ไขค่าระดับระบบ
- ระบบต้องป้องกันการบันทึกข้อมูลที่ไม่ครบถ้วน ไม่ถูกต้อง หรือซ้ำ
- การเปลี่ยนแปลงที่กระทบความปลอดภัยหรือการทำงานหลักต้องมีการยืนยันและบันทึก audit log
- การตั้งค่าบางรายการที่สำคัญต้องมีการอนุมัติจาก Super Admin หรือผู้มีสิทธิ์เพิ่มเติมตามนโยบายของระบบ

## Requirements
- FR-ADM-01 ระบบต้องแสดงเมนูและฟังก์ชันที่ผู้ดูแลมีสิทธิ์เข้าถึงเท่านั้น    <- UC-17 requirement 1
- FR-ADM-02 ระบบต้องตรวจสอบความถูกต้องของข้อมูลก่อนบันทึก เช่น ฟิลด์ที่จำเป็น รูปแบบข้อมูล ค่าที่ไม่ซ้ำ และค่าที่ขัดต่อกฎหมายหรือนโยบายของระบบ    <- UC-17 requirement 2
- FR-ADM-03 ระบบต้องอนุญาตให้ Admin จัดการผู้ใช้และบทบาทที่ได้รับมอบหมาย และต้องบังคับให้รายการที่เป็นค่าตั้งค่าสำคัญต้องได้รับการอนุมัติจาก Super Admin ก่อนมีผลบังคับใช้    <- UC-17 requirement 3
- FR-ADM-04 ระบบต้องแสดงสถานะปัจจุบันและความพร้อมใช้งานของบริการให้ผู้ดูแลเห็นได้ เช่น Online, Offline, Error, Healthy, Unhealthy
- FR-ADM-05 ระบบต้องบันทึกประวัติการเปลี่ยนแปลงที่สำคัญพร้อมข้อมูลผู้ทำรายการ เวลา และรายละเอียดการเปลี่ยนแปลง    <- UC-17 requirement 4

## Quality Requirements
- NFR-SEC-01 ต้องใช้สิทธิ์ระดับผู้ดูแลหรือสูงกว่าในการเข้าถึงการจัดการระบบ
- NFR-SEC-02 การเปลี่ยนแปลงที่เป็นค่าตั้งค่าสำคัญต้องมีการอนุมัติจาก Super Admin ก่อนมีผลบังคับใช้
- NFR-AUD-01 ทุกการเปลี่ยนแปลงสำคัญต้องมี audit log ที่สามารถระบุผู้ทำรายการ เวลา และรายละเอียดการเปลี่ยนแปลงได้

## Acceptance Criteria
- [ ] AC-ADM-01 (FR-ADM-01)
      Given ผู้ดูแลระบบ login ด้วยสิทธิ์ที่อนุญาต
            When  เข้าหน้า "จัดการระบบ"
            Then  ระบบแสดงเฉพาะเมนูและฟังก์ชันที่ผู้ดูแลมีสิทธิ์ใช้งาน
- [ ] AC-ADM-02 (FR-ADM-02)
      Given ข้อมูลที่กรอกไม่ครบถ้วนหรือไม่ถูกต้อง
            When  ผู้ดูแลกดบันทึก
            Then  ระบบปฏิเสธการบันทึกและแสดงข้อความแจ้งข้อผิดพลาด
- [ ] AC-ADM-03 (FR-ADM-03)
      Given มีการเปลี่ยนแปลงข้อมูลที่เป็นค่าตั้งค่าสำคัญ
            When  Admin ส่งการเปลี่ยนแปลงเพื่อบันทึก
            Then  ระบบต้องขอการอนุมัติจาก Super Admin ก่อนมีผลบังคับใช้
- [ ] AC-ADM-04 (FR-ADM-04)
      Given ผู้ดูแลเข้าดูหน้า "จัดการระบบ"
            When  ระบบแสดงข้อมูลสถานะบริการ
            Then  ระบบแสดงสถานะปัจจุบันและความพร้อมใช้งานของบริการตามค่า Online/Offline/Error/Healthy/Unhealthy
- [ ] AC-ADM-05 (FR-ADM-05)
      Given มีการเปลี่ยนแปลงข้อมูลสำคัญ
            When  บันทึกข้อมูล
            Then  ระบบบันทึกประวัติการเปลี่ยนแปลงพร้อมผู้ทำรายการ เวลา และรายละเอียดการเปลี่ยนแปลง
