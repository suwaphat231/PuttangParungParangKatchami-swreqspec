# Feature: จัดการระบบ
Spec ID: SPEC-17 | Source: Use Case Diagram UC-17 | Use case: UC-17
Owner: ทีม A | Status: Clarified Draft v2 | Updated: 2569-09-19

## Goal
ผู้ดูแลระบบสามารถจัดการข้อมูลตั้งค่าและรายการระบบที่อนุญาตให้ใช้งานภายในระบบได้อย่างปลอดภัย โดยครอบคลุมการจัดการผู้ใช้และบทบาท การกำหนดค่าตั้งค่าและค่าตั้งค่าสำคัญ การตรวจสอบสถานะบริการ และการบันทึกประวัติการเปลี่ยนแปลง (audit log) เพื่อให้ระบบทำงานได้ถูกต้องตามนโยบายความปลอดภัยและสามารถตรวจสอบได้ว่ามีการเปลี่ยนแปลงใดเกิดขึ้น เมื่อใครทำ และยืนยันด้วยใคร

## Actors and Roles
- นักศึกษา: เป็นผู้ใช้งานทั่วไปที่มีสิทธิ์ใช้งานตามบทบาทของผู้ใช้งานแต่ไม่มีสิทธิ์จัดการระบบระดับผู้ดูแล
- อาจารย์: เป็นผู้มีสิทธิ์ตรวจสอบและอนุมัติการเปลี่ยนแปลงที่เป็นค่าตั้งค่าสำคัญตามนโยบายของระบบ
- เจ้าหน้าที่: เป็นผู้ดูแลระบบที่ได้รับมอบหมายให้จัดการผู้ใช้ บทบาท และค่าตั้งค่าในขอบเขตที่ได้รับอนุญาต
- System Owner: เป็นผู้ดูแลระบบระดับสูง มีสิทธิ์ดูและจัดการค่าระดับระบบหลักและค่าตั้งค่าสำคัญตามนโยบายของระบบ

## Assumptions
- AS-01 Use Case นี้ครอบคลุมการจัดการผู้ใช้และบทบาท การตั้งค่าและการควบคุมระบบ การตรวจสอบสถานะบริการ และการบันทึกประวัติการเปลี่ยนแปลง (audit log) ภายในระบบ
- AS-02 ค่าตั้งค่าสำคัญหมายถึงค่าที่ส่งผลต่อความปลอดภัยหรือการทำงานหลักของระบบ เช่น การเปิด-ปิดฟังก์ชันระดับระบบ การโอนสิทธิ์หรือบทบาทระดับระบบ การกำหนดค่าความปลอดภัย การกำหนดวงเงินหรือขั้นต่ำที่มีผลต่อการทำงานหลัก และค่าที่มีผลต่อความพร้อมใช้งานของบริการ ค่าดังกล่าวต้องอยู่ในสถานะ Pending Approval จนกว่าจะได้รับการอนุมัติจากอาจารย์หรือผู้มีสิทธิ์ที่เกี่ยวข้องก่อนมีผลบังคับใช้
- AS-03 ผู้ดูแลระบบมี 4 ระดับสิทธิ์หลักคือ นักศึกษา, อาจารย์, เจ้าหน้าที่, และ System Owner โดยแต่ละระดับมีหน้าที่และสิทธิ์ที่ต่างกันตามนโยบายระบบ
- AS-04 Audit log จะบันทึกเฉพาะการเปลี่ยนแปลงที่สำคัญเท่านั้น พร้อมข้อมูลผู้ทำรายการ เวลา สถานะก่อนและหลังการเปลี่ยนแปลง และรายละเอียดการเปลี่ยนแปลง
- AS-05 การตรวจสอบสถานะบริการหมายถึงการดูสถานะปัจจุบันและความพร้อมใช้งานของบริการ เช่น Online, Offline, Error, Healthy, Unhealthy
- AS-06 ระบบต้องป้องกันการอนุมัติด้วยตนเอง (self-approval) และต้องไม่ให้ค่าตั้งค่าสำคัญมีผลบังคับใช้ก่อนผ่านการอนุมัติ

## Scope
### In scope
- จัดการผู้ใช้และบทบาทที่ระบบอนุญาตให้มีสิทธิ์ใช้งาน
- จัดการค่าตั้งระบบที่มีผลต่อการทำงานของระบบ
- จัดการค่าตั้งค่าสำคัญที่ต้องมีการอนุมัติจาก Super Admin ตามนโยบาย
- ตรวจสอบสถานะบริการและความพร้อมใช้งานปัจจุบัน
- บันทึกประวัติการเปลี่ยนแปลงของข้อมูลที่สำคัญ (audit log)
- แสดงสถานะ Pending Approval เมื่อมีการเปลี่ยนแปลงที่รออนุมัติ
### Out of scope
- อนุมัติสิทธิ์การเข้าใช้งาน (UC-18)
- การกำหนดนโยบายธุรกิจภายนอกระบบที่ไม่ใช่การตั้งค่าในระบบ
- การเริ่ม/หยด/รีสตาร์ทบริการโดยตรง เว้นแต่จะถูกระบุเป็นส่วนหนึ่งของ Use Case แยกต่างหาก

## Constraints
- เฉพาะผู้ดูแลระบบที่ได้รับสิทธิ์เท่านั้นที่สามารถเข้าถึงเมนูและฟังก์ชันจัดการระบบ
- ระดับสิทธิ์หลักประกอบด้วย นักศึกษา, อาจารย์, เจ้าหน้าที่, และ System Owner โดย นักศึกษาเป็นผู้ใช้งานทั่วไป, อาจารย์มีสิทธิ์อนุมัติการเปลี่ยนแปลงสำคัญตามนโยบายระบบ, เจ้าหน้าที่ดู/จัดการค่าตั้งค่าและผู้ใช้ที่ได้รับมอบหมาย, และ System Owner ดูแลเกี่ยวกับระบบเป็นหลักและดู/แก้ไขค่าระดับระบบ
- ระบบต้องป้องกันการบันทึกข้อมูลที่ไม่ครบถ้วน ไม่ถูกต้อง หรือซ้ำ
- การเปลี่ยนแปลงที่กระทบความปลอดภัยหรือการทำงานหลักต้องมีการยืนยันและบันทึก audit log ก่อนให้มีผลบังคับใช้
- การตั้งค่าบางรายการที่สำคัญต้องมีการอนุมัติจาก อาจารย์ หรือผู้มีสิทธิ์เพิ่มเติมตามนโยบายของระบบ
- ระบบต้องแสดงสถานะอัปเดตล่าสุดของบริการและบันทึกเวลาเมื่อสถานะเปลี่ยนแปลง
- ผู้ใช้งานไม่สามารถอนุมัติการเปลี่ยนแปลงที่ตนเองส่งคำขอได้

## Requirements
- FR-ADM-01 ระบบต้องแสดงเมนูและฟังก์ชันที่ผู้ดูแลมีสิทธิ์เข้าถึงเท่านั้น    <- UC-17 requirement 1
- FR-ADM-02 ระบบต้องตรวจสอบความถูกต้องของข้อมูลก่อนบันทึก เช่น ฟิลด์ที่จำเป็น รูปแบบข้อมูล ค่าที่ไม่ซ้ำ และค่าที่ขัดต่อกฎหมายหรือนโยบายของระบบ    <- UC-17 requirement 2
- FR-ADM-03 ระบบต้องอนุญาตให้ เจ้าหน้าที่ จัดการผู้ใช้และบทบาทที่ได้รับมอบหมาย และต้องบังคับให้รายการที่เป็นค่าตั้งค่าสำคัญต้องอยู่ในสถานะ Pending Approval และได้รับการอนุมัติจาก อาจารย์ ก่อนมีผลบังคับใช้    <- UC-17 requirement 3
- FR-ADM-04 ระบบต้องแสดงสถานะปัจจุบันและความพร้อมใช้งานของบริการให้ผู้ดูแลเห็นได้ เช่น Online, Offline, Error, Healthy, Unhealthy พร้อมระบุเวลาของสถานะล่าสุด
- FR-ADM-05 ระบบต้องบันทึกประวัติการเปลี่ยนแปลงที่สำคัญพร้อมข้อมูลผู้ทำรายการ เวลา สถานะก่อนและหลังการเปลี่ยนแปลง และรายละเอียดการเปลี่ยนแปลง    <- UC-17 requirement 4
- FR-ADM-06 ระบบต้องปฏิเสธการอนุมัติการเปลี่ยนแปลงที่ผู้ส่งคำขอเป็นผู้อนุมัติเอง และต้องไม่ให้ค่าตั้งค่าสำคัญมีผลบังคับใช้จนกว่าจะได้รับอนุมัติจากผู้มีสิทธิ์ที่ถูกต้องตามบทบาทของอาจารย์หรือ System Owner

## Quality Requirements
- NFR-SEC-01 ต้องใช้สิทธิ์ระดับผู้ดูแลหรือสูงกว่าในการเข้าถึงการจัดการระบบ
- NFR-SEC-02 การเปลี่ยนแปลงที่เป็นค่าตั้งค่าสำคัญต้องอยู่ในสถานะ Pending Approval และต้องมีการอนุมัติจาก อาจารย์ หรือ System Owner ก่อนมีผลบังคับใช้
- NFR-AUD-01 ทุกการเปลี่ยนแปลงสำคัญต้องมี audit log ที่สามารถระบุผู้ทำรายการ เวลา สถานะก่อน/หลัง และรายละเอียดการเปลี่ยนแปลงได้
- NFR-AVAIL-01 ระบบต้องสามารถแสดงสถานะปัจจุบันและเวลาอัปเดตล่าสุดของบริการให้ผู้ดูแลทราบได้ทันที

## Acceptance Criteria
- [ ] AC-ADM-01 (FR-ADM-01)
      Given ผู้ดูแลระบบ login ด้วยสิทธิ์ที่อนุญาต
            When  เข้าหน้า "จัดการระบบ"
            Then  ระบบแสดงเฉพาะเมนูและฟังก์ชันที่ผู้ดูแลมีสิทธิ์ใช้งาน
- [ ] AC-ADM-02 (FR-ADM-02)
      Given ข้อมูลที่กรอกไม่ครบถ้วนหรือไม่ถูกต้อง
            When  ผู้ดูแลกดบันทึก
            Then  ระบบปฏิเสธการบันทึกและแสดงข้อความแจ้งข้อผิดพลาด
- [ ] AC-ADM-03 (FR-ADM-03)
      Given มีการเปลี่ยนแปลงข้อมูลที่เป็นค่าตั้งค่าสำคัญ
            When  เจ้าหน้าที่ ส่งการเปลี่ยนแปลงเพื่อบันทึก
            Then  ระบบต้องระบุสถานะเป็น "Pending Approval" และไม่ให้มีผลบังคับใช้จนกว่าจะได้รับการอนุมัติจาก อาจารย์
- [ ] AC-ADM-04 (FR-ADM-04)
      Given ผู้ดูแลเข้าดูหน้า "จัดการระบบ"
            When  ระบบแสดงข้อมูลสถานะบริการ
            Then  ระบบแสดงสถานะปัจจุบัน ความพร้อมใช้งาน และเวลาของสถานะล่าสุดตามค่า Online/Offline/Error/Healthy/Unhealthy
- [ ] AC-ADM-05 (FR-ADM-05)
      Given มีการเปลี่ยนแปลงข้อมูลสำคัญ
            When  บันทึกข้อมูล
            Then  ระบบบันทึกประวัติการเปลี่ยนแปลงพร้อมผู้ทำรายการ เวลา สถานะก่อน/หลัง และรายละเอียดการเปลี่ยนแปลง
- [ ] AC-ADM-06 (FR-ADM-06)
      Given ผู้ส่งคำขอการเปลี่ยนแปลงเป็นคนเดียวกับผู้อนุมัติ
            When  ระบบประมวลผลการอนุมัติ
            Then  ระบบปฏิเสธการอนุมัติและไม่ให้ค่าตั้งค่าสำคัญมีผลบังคับใช้
