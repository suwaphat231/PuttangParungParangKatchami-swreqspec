# Plan v2 - UC-18: อนุมัติสิทธิ์การเข้าใช้งาน

## วัตถุประสงค์
ปรับปรุงสเปคสำหรับการอนุมัติสิทธิ์การเข้าใช้งานให้ชัดเจนและสามารถตรวจสอบได้ว่า:
- ระบบแสดงคำขอที่รออนุมัติอย่างไร
- ผู้มีสิทธิ์อนุมัติมีสถานะอย่างไร
- บทบาทและสิทธิ์ที่ร้องขอต้องสอดคล้องกับ role matrix หรือไม่
- การปฏิเสธต้องมีเหตุผลที่บันทึกไว้
- การเปลี่ยนแปลงสิทธิ์ที่เกิดจากข้อมูลผิดพลาดสามารถแก้ไขได้โดย Admin หรือผู้ดูแลระบบ โดยไม่ต้องอนุมัติใหม่

## สรุปการปรับปรุง
1. เพิ่มความชัดเจนว่าคำขอที่รออนุมัติต้องมีข้อมูลผู้ใช้ บทบาทที่ขอ สิทธิ์ที่ร้องขอ และเวลาแจ้งคำขอ
2. กำหนดว่าระบบต้องตรวจสอบ role matrix ก่อนอนุมัติคำขอ
3. กำหนดให้ระบบปฏิเสธคำขอเมื่อบทบาทหรือสิทธิ์อยู่นอกรายการที่อนุญาต
4. บันทึกข้อมูลผลการพิจารณา ได้แก่ สถานะ ผู้อนุมัติ เวลา และเหตุผลปฏิเสธ
5. ระบุให้เฉพาะผู้ที่มีสถานะ approver เท่านั้นที่สามารถอนุมัติหรือปฏิเสธคำขอ
6. เพิ่มคำอธิบายว่า “เปลี่ยนแปลงสิทธิ์” หมายถึงการแก้ไขข้อมูลผู้ใช้เมื่อข้อมูลผิดพลาด เช่น นักศึกษาเป็นอาจารย์ หรือบทบาท/สิทธิ์กำหนดผิด
7. ยืนยันว่า Admin หรือผู้ดูแลระบบสามารถแก้ไขข้อมูลดังกล่าวได้ทันทีโดยไม่ต้องอนุมัติใหม่

## Open Questions ที่ยังเหลือ
- ผู้มีสิทธิ์อนุมัติ (Approver) ต้องมีสถานะที่ชัดเจนในระบบหรือไม่
- ในกรณีที่มีข้อมูลผู้ใช้ผิดพลาด ควรให้ Admin หรือผู้ดูแลระบบสามารถแก้ไขได้ทันทีหรือไม่
- บัญชีใดต้องอนุมัติด้วยเจ้าหน้าที่อีกคนหรือไม่
- ระบบแจ้งผลคำขอให้ผู้ยื่นคำขอทางใด

## Assumptions
- ระบบมี role matrix ที่กำหนดบทบาทและสิทธิ์ที่อนุญาต
- ผู้มีสิทธิ์อนุมัติมีสถานะที่ชัดเจนในระบบ
- การปฏิเสธคำขอต้องมีเหตุผลและบันทึกไว้
- การเปลี่ยนแปลงสิทธิ์ที่เกิดจากความผิดพลาดสามารถแก้ไขได้ทันทีโดยผู้ดูแลระบบ
