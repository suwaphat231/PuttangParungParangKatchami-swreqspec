# Feature: อนุมัติสิทธิ์การเข้าใช้งาน
Spec ID: SPEC-18-18- | Source: Use Case Diagram UC-18 | Use case: UC-18
Owner: ทีม A | Status: Draft v2 | Updated: 2569-09-19

## Goal
ผู้ดูแลระบบตรวจสอบคำขอสิทธิ์การเข้าใช้งานของผู้ใช้ และอนุมัติหรือปฏิเสธตามบทบาทและสิทธิ์ที่ได้รับอนุญาตภายใต้แผนผังบทบาท (role matrix) ของระบบ เพื่อให้ผู้ใช้ได้รับสิทธิ์ที่เหมาะสมและมีการควบคุมความปลอดภัยตามนโยบาย IAM

## Scope
### In scope
- ดูรายการคำขอสิทธิ์การเข้าใช้งานที่อยู่ในสถานะรออนุมัติ
- ตรวจสอบข้อมูลผู้ใช้งาน บทบาทที่ขอ และสิทธิ์ที่ร้องขอ
- ปฏิเสธหรืออนุมัติคำขอโดยผู้มีสิทธิ์รับผิดชอบ
- บันทึกผลการพิจารณา ผู้อนุมัติ เวลา และเหตุผล (กรณีปฏิเสธ)
- จำกัดการอนุมัติให้เฉพาะบทบาทหรือสิทธิ์ที่อยู่ในรายการที่อนุญาตเท่านั้น
### Out of scope
- เข้าสู่ระบบ (UC-04)
- จัดการระบบ (UC-17)
- การออกแบบนโยบาย IAM ระดับองค์กรหรือบทบาทใหม่ที่ไม่ได้กำหนดใน role matrix



## Constraints
- สิทธิ์หรือบทบาทที่อนุมัติต้องสอดคล้องกับ role matrix และนโยบาย IAM ที่กำหนด
- ระบบต้องปฏิเสธคำขอที่มีบทบาทหรือสิทธิ์อยู่นอกรายการที่อนุญาต
- การปฏิเสธคำขอต้องมีเหตุผลและไม่สามารถบันทึกเป็นเว้นว่างได้
- การอนุมัติหรือปฏิเสธต้องระบุผู้อนุมัติและเวลาของการพิจารณา

## Requirements
- FR-IAM-01 ระบบต้องแสดงรายการคำขอสิทธิ์การเข้าใช้งานที่อยู่ในสถานะรออนุมัติ พร้อมข้อมูลผู้ใช้ บทบาทที่ขอ สิทธิ์ที่ร้องขอ และเวลาแจ้งคำขอ    <- UC-18 requirement 1
- FR-IAM-02 ระบบต้องตรวจสอบว่าบทบาทและสิทธิ์ที่ร้องขออยู่ภายใต้ role matrix ที่อนุญาตก่อนอนุมัติคำขอ    <- UC-18 requirement 2
- FR-IAM-03 ระบบต้องปฏิเสธคำขอและแสดงข้อความแจ้งข้อผิดพลาดเมื่อบทบาทหรือสิทธิ์ไม่อยู่ในรายการที่อนุญาต    <- UC-18 requirement 2
- FR-IAM-04 ระบบต้องบันทึกผลการพิจารณา ได้แก่ สถานะอนุมัติ/ปฏิเสธ ผู้อนุมัติ เวลาอนุมัติ และเหตุผลเมื่อปฏิเสธ    <- UC-18 requirement 3
- FR-IAM-05 ระบบต้องห้ามการอนุมัติจากผู้ใช้งานที่ไม่ได้รับสิทธิ์เป็น approver

## Quality Requirements
- NFR-SEC-01 การเปลี่ยนแปลงสิทธิ์ต้องได้รับการยืนยันโดยผู้มีอำนาจอนุมัติที่ได้รับสิทธิ์เท่านั้น
- NFR-SEC-02 บทบาทหรือสิทธิ์ที่ไม่อยู่ภายใต้ role matrix ต้องถูกปฏิเสธโดยระบบและไม่สามารถมีผลบังคับใช้ได้
- NFR-AUD-01 ระบบต้องบันทึกประวัติการเปลี่ยนแปลงสิทธิ์พร้อมข้อมูลผู้อนุมัติ เวลา และเหตุผลการตัดสินใจ

## Acceptance Criteria
- [ ] AC-IAM-01 (FR-IAM-01)
      Given มีคำขอสิทธิ์การเข้าใช้งานในสถานะรออนุมัติ
            When  ผู้ดูแลระบบเปิดหน้ารายการคำขอ
            Then  ระบบแสดงข้อมูลผู้ใช้ บทบาทที่ขอ สิทธิ์ที่ร้องขอ และเวลาของคำขออย่างครบถ้วน
- [ ] AC-IAM-02 (FR-IAM-02, FR-IAM-03)
      Given บทบาทหรือสิทธิ์ที่ร้องขอไม่อยู่ใน role matrix ที่อนุญาต
            When  ผู้ดูแลระบบพยายามยืนยันคำขอ
            Then  ระบบปฏิเสธการอนุมัติและแสดงข้อความแจ้งว่าไม่อยู่ในรายการที่อนุญาต
- [ ] AC-IAM-03 (FR-IAM-04)
      Given มีคำขอที่ผ่านการตรวจสอบแล้ว
            When  ผู้มีสิทธิ์อนุมัติยืนยันคำขอ
            Then  ระบบบันทึกสถานะอนุมัติ ผู้อนุมัติ เวลา และปรับสถานะคำขอเป็น Approved
- [ ] AC-IAM-04 (FR-IAM-04)
      Given ผู้มีสิทธิ์อนุมัติปฏิเสธคำขอ
            When  ระบุเหตุผลปฏิเสธและบันทึกผล
            Then  ระบบบันทึกสถานะปฏิเสธ ผู้อนุมัติ เวลาปฏิเสธ และเหตุผลปฏิเสธ
- [ ] AC-IAM-05 (FR-IAM-05, NFR-SEC-01)
      Given ผู้ใช้งานไม่มีสิทธิ์เป็น approver
            When  พยายามอนุมัติหรือปฏิเสธคำขอ
            Then  ระบบปฏิเสธการดำเนินการและไม่บันทึกผลการอนุมัติ

## Assumptions & Open Questions
- ASM-01 มี role matrix ที่กำหนดไว้
- ASM-02 การเปลี่ยนแปลงสิทธิ์หมายถึงการแก้ไขข้อมูลผู้ใช้เมื่อมีข้อมูลผิดพลาด เช่น นักศึกษาเปลี่ยนเป็นอาจารย์ หรือบทบาท/สิทธิ์กำหนดผิด โดย Admin หรือผู้ดูแลระบบสามารถแก้ไขได้ทันที โดยไม่ต้องมีการอนุมัติใหม่
- Q-01 ผู้มีสิทธิ์อนุมัติ (Approver) ต้องมีสถานะที่ชัดเจนในระบบเพื่อให้ระบบสามารถตรวจสอบสิทธิ์อนุมัติได้หรือไม่?
- Q-02 ในกรณีที่มีข้อมูลผู้ใช้ผิดพลาด เช่น นักศึกษาเป็นอาจารย์ แต่กำหนดบทบาทหรือสิทธิ์ผิด ต้องให้ Admin หรือผู้ดูแลระบบสามารถแก้ไขให้ถูกต้องได้ทันทีโดยไม่ต้องมีการอนุมัติใหม่หรือไม่?
- Q-03 บัญชีใดต้องอนุมัติด้วยเจ้าหน้าที่อีกคนหรือไม่? -> ต้องยืนยันนโยบาย IAM
- Q-04 มีการแจ้งผลคำขอให้ผู้ยื่นคำขอทราบผ่านอีเมลหรือระบบหรือไม่? -> ต้องยืนยันภารกิจทางการสื่อสาร
