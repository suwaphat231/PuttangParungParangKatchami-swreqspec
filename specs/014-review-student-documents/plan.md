# Plan: ตรวจสอบเอกสารนักศึกษา (UC-14)
Spec Target: [specs/14-14-review-student-documents/spec.md](specs/14-14-review-student-documents/spec.md) (v2)

## 1. การรองรับเงื่อนไขใน Spec (Constraints & Scope)
- **รายการเอกสารบังคับ (FR-OFC-01):** ดึง checklist จากประกาศรับสมัครแต่ละฉบับเป็นแหล่งข้อมูลหลัก (Single Source of Truth)
- **ผลการตรวจสอบ (FR-OFC-02):** บันทึกผลการตรวจสอบเป็น ผ่าน / ไม่ผ่าน / ส่งกลับเพื่อแก้ไข พร้อมเหตุผลและรายการเอกสารที่มีปัญหา
- **การส่งกลับเพื่อแก้ไข (FR-OFC-03):** บังคับให้เลือกเอกสารที่มีปัญหาและระบุเหตุผลก่อนยืนยัน พร้อมแจ้งนักศึกษาผ่านแอปและอีเมล
- **การจำกัดสิทธิ์ (NFR-SEC-01):** กรองข้อมูลและใบสมัครตามบทบาทของผู้ใช้งาน
- **Audit log (NFR-AUD-01):** บันทึกประวัติการตรวจสอบแบบ immutable
- **การแจ้งเตือน (NFR-NOT-01):** ส่งประกาศแจ้งกลับไปยังนักศึกษาผ่านแอปเป็นหลักและอีเมลเป็นช่องทางเสริม

## 2. รายการ task
- [ ] **T-01:** กำหนดลำดับการดึง checklist เอกสารจากประกาศรับสมัครและเชื่อมกับใบสมัครที่เลือก
- [ ] **T-02:** บันทึกผลการตรวจสอบเป็น ผ่าน / ไม่ผ่าน / ส่งกลับเพื่อแก้ไข พร้อมเหตุผลและรายการเอกสารที่มีปัญหา
- [ ] **T-03:** บังคับให้เลือกเอกสารที่มีปัญหาและระบุเหตุผลก่อนยืนยันการส่งกลับเพื่อแก้ไข
- [ ] **T-04:** ตรวจสอบสิทธิ์การเข้าถึงและการแก้ไขตามบทบาทผู้ใช้งาน

- [ ] **T-06:** กำหนดกระบวนการแจ้งเตือนผ่านระบบแอปและอีเมล
- [ ] **T-07:** ทดสอบ acceptance criteria ทั้งหมด

## 3. รายการตรวจสอบ (Acceptance Criteria Checklist)
- [ ] **AC-OFC-01:** ดึง checklist เอกสารจากประกาศรับสมัครและแสดงอัตโนมัติเมื่อเปิดใบสมัคร
- [ ] **AC-OFC-02:** บันทึกผลตรวจสอบเป็น ผ่าน / ไม่ผ่าน / ส่งกลับเพื่อแก้ไข พร้อมเหตุผลและบันทึก audit log
- [ ] **AC-OFC-03:** บังคับให้เลือกเอกสารที่มีปัญหาและระบุเหตุผลก่อนยืนยันส่งกลับ พร้อมแจ้งนักศึกษา

## 4. วัตถุประสงค์ของแผน
- ทำให้กระบวนการตรวจสอบเอกสารเป็นไปตามข้อกำหนด UC-14 และปัจจัยด้านความปลอดภัย/การบันทึกประวัติ
- ลดความคลุมเครือของ checklist, status, และ role-based access
- สร้าง traceability ที่สามารถตรวจสอบได้จาก requirement → implementation → test
