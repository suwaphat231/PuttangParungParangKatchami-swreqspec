### T-01: กำหนดสิทธิ์การเข้าถึงเอกสารและข้อมูลที่ต้องตรวจสอบ
- รองรับ: FR-DOC-01, NFR-SEC-01, ASM-01
- ตรวจด้วย: AC-DOC-03
- ไฟล์ที่แตะ: ไม่มีไฟล์ implementation หรือ test ที่มีอยู่จริงใน repo สำหรับงานนี้
- ต้องทำหลัง: -
- เสร็จเมื่อ:
  - ระบุสิทธิ์ในการเข้าถึงเอกสารให้ชัดเจนตาม FR-DOC-01 และ NFR-SEC-01: เอกสารของผู้สมัครต้องเปิดให้เฉพาะผู้ใช้ที่มีสิทธิ์เข้าถึงตามประกาศ/บทบาทที่เกี่ยวข้องกับการตรวจเอกสารเท่านั้น; ผู้ใช้ที่ไม่มีสิทธิ์ต้องไม่สามารถเข้าถึงเอกสารได้
  - ระบุประเภทเอกสารที่ต้องใช้ตามประกาศและสอดคล้องกับ ASM-01: ระบบต้องใช้เอกสารตามประเภทที่ประกาศระบุไว้ในประกาศรับสมัครหรือประกาศที่เกี่ยวข้องและไม่ขยายประเภทเอกสารเกินกว่าที่กำหนดไว้
  - กำหนดเงื่อนไขที่ต้องปฏิเสธการเข้าถึงเมื่อผู้ใช้ไม่มีสิทธิ์: ก่อนเปิดหรือแสดงเอกสาร ระบบต้องตรวจสอบสิทธิ์ของผู้ใช้ หากไม่มีสิทธิ์ต้องปฏิเสธการเข้าถึงทันที และไม่เปิดเผยเนื้อหาเอกสารหรือข้อมูลที่เกี่ยวข้องตาม AC-DOC-03
  - กำหนดผลลัพธ์เมื่อได้รับอนุญาตและเมื่อถูกปฏิเสธให้ชัดเจน: กรณีมีสิทธิ์ให้สามารถเข้าถึงเอกสารเพื่อพิจารณาความครบถ้วนและความถูกต้องได้; กรณีไม่มีสิทธิ์ให้ส่งกลับผลลัพธ์ปฏิเสธการเข้าถึงตามกติกาใน AC-DOC-03
  - ตรวจสอบความสอดคล้องกับ AC-DOC-03: Given ไม่มีสิทธิ์ดูเอกสาร When เปิดเอกสาร Then ระบบปฏิเสธการเข้าถึง; ดังนั้น T-01 ต้องเป็นฐานสำหรับการกำหนดสิทธิ์ก่อน T-02 และ T-06
  - ข้อความและเงื่อนไขนี้ต้องยึดตาม spec.md และ ASM-01 โดยไม่เพิ่ม scope หรือ requirement ใหม่ และยังคง Q-01 เป็น Open Question ไว้ตามเดิม
- สถานะ: Done

### T-02: แสดงเอกสารที่ผู้สมัครส่งมาให้พิจารณา
- รองรับ: FR-DOC-01, NFR-SEC-01, ASM-01
- ตรวจด้วย: AC-DOC-03
- ไฟล์ที่แตะ: ไม่มีไฟล์ implementation หรือ test ที่มีอยู่จริงใน repo สำหรับงานนี้
- ต้องทำหลัง: T-01
- เสร็จเมื่อ:
  - ระบุว่าระบบต้องแสดงเอกสารของผู้สมัครตามสิทธิ์เท่านั้น: ตาม FR-DOC-01 ระบบต้องแสดงเอกสารของผู้สมัครเฉพาะเมื่อผู้ใช้มีสิทธิ์เข้าถึงตามข้อกำหนด และไม่อนุญาตให้แสดงแก่ผู้ใช้ที่ไม่มีสิทธิ์
  - ระบุว่าผู้ใช้ต้องผ่านการตรวจสอบสิทธิ์ก่อนเข้าถึงเอกสาร: ก่อนเปิดหรือแสดงเอกสาร ระบบต้องตรวจสอบสิทธิ์ของผู้ใช้ก่อนให้เข้าถึงเนื้อหาเอกสารหรือรายการเอกสารที่เกี่ยวข้อง
  - ระบุผลลัพธ์เมื่อไม่มีสิทธิ์: ตาม AC-DOC-03 หากผู้ใช้ไม่มีสิทธิ์เปิดเอกสาร ระบบต้องปฏิเสธการเข้าถึงทันที และไม่อนุญาตให้เข้าถึงเอกสารนั้น
  - ระบุว่าเอกสารที่แสดงต้องเป็นประเภทที่กำหนดไว้ในประกาศ/ASM-01: ระบบต้องแสดงเฉพาะเอกสารที่เป็นประเภทตามประกาศที่ระบุใน ASM-01 เท่านั้น และต้องไม่ขยายประเภทเอกสารเกินที่ spec.md และ ASM-01 กำหนด
  - ระบุการแสดงเอกสารเพื่อให้ตรวจสอบความครบถ้วนและความถูกต้องตาม Scope: การแสดงเอกสารต้องช่วยให้ผู้ตรวจสอบสามารถเปิดดูเอกสารของผู้สมัครเพื่อพิจารณาความครบถ้วนและความถูกต้องตามขอบเขตของ UC-10 โดยไม่ออกนอก Scope ที่ระบุไว้ใน spec.md
  - จำกัดการกำหนดรายละเอียดการแสดงผล: ห้ามกำหนดรายละเอียดการแสดงผลเพิ่มเติม เช่น สถานะการส่ง ชื่อฟิลด์ metadata หรือข้อมูลแสดงผลอื่น ๆ ที่ไม่มีการระบุรองรับใน spec.md หรือ ASM-01
  - ตรวจสอบความสอดคล้องกับ FR-DOC-01, NFR-SEC-01, ASM-01 และ AC-DOC-03: ผู้มีสิทธิ์สามารถเข้าถึงเอกสารได้; ผู้ไม่มีสิทธิ์ต้องถูกปฏิเสธ; และเอกสารที่แสดงต้องเป็นชนิดที่กำหนดตามประกาศ
  - คง Q-01 ไว้ตามเดิม และใช้เฉพาะข้อมูลที่มีใน spec.md กับ ASM-01 เท่านั้น โดยไม่เพิ่ม Scope หรือ Requirement ใหม่ และไม่ข้ามไปสู่ T-03 ถึง T-06
- สถานะ: Done

### T-03: บันทึกผลการตรวจสอบเอกสารเมื่ออนุมัติ
- รองรับ: FR-DOC-02
- ตรวจด้วย: AC-DOC-01
- ไฟล์ที่แตะ: ไม่มีไฟล์ implementation หรือ test ที่มีอยู่จริงใน repo สำหรับงานนี้
- ต้องทำหลัง: T-01, T-02
- เสร็จเมื่อ:
  - ระบุขั้นตอนการบันทึกผลการตรวจสอบเมื่อเอกสารถูกต้องครบและอาจารย์อนุมัติ: เมื่อเอกสารผ่านการตรวจสอบตาม Scope และผู้มีสิทธิ์ทำการอนุมัติ ระบบต้องบันทึกผลการตรวจสอบตาม FR-DOC-02
  - ตรวจสอบความสอดคล้องกับ AC-DOC-01: Given เอกสารถูกต้องครบ When อาจารย์อนุมัติ Then ระบบบันทึกผลอนุมัติ; หากเอกสารยังไม่ครบถ้วนหรือไม่ถูกต้อง จะไม่ถือว่าเป็นเงื่อนไขการอนุมัติ
  - ระบุข้อมูลที่บันทึกให้สอดคล้องกับ FR-DOC-02 เท่าที่ spec.md รองรับ: ผู้ตรวจสอบ ผลการตรวจสอบ วันที่/เวลา และเอกสารที่เกี่ยวข้อง เพื่อให้สามารถติดตามผลการตรวจสอบและเชื่อมโยงกับเอกสารที่อนุมัติได้ โดยไม่กำหนดฟิลด์หรือ API เพิ่มเติมที่ spec.md ไม่ระบุชัดเจน
  - ระบุผลลัพธ์หลังบันทึกสำเร็จ: ระบบต้องยืนยันว่ามีการบันทึกผลอนุมัติสำหรับเอกสารที่ได้รับอนุมัติแล้ว และผลลัพธ์นี้ต้องสอดคล้องกับ AC-DOC-01
  - ระบุกรณีบันทึกไม่สำเร็จ: หากระหว่างการบันทึกผิดพลาด ระบบต้องไม่ถือว่าการอนุมัติสำเร็จจนกว่าจะมีการยืนยันว่าบันทึกข้อมูลเรียบร้อยแล้ว
  - ใช้เฉพาะข้อมูลที่มีใน spec.md เท่านั้น ห้ามเพิ่ม Scope หรือ Requirement ใหม่ และไม่ข้ามไปสู่ T-04 ถึง T-06
- สถานะ: Done

### T-04: บังคับให้ระบุเหตุผลเมื่อไม่อนุมัติหรือส่งกลับ
- รองรับ: FR-DOC-03
- ตรวจด้วย: AC-DOC-02
- ไฟล์ที่แตะ: ไม่มีไฟล์ implementation หรือ test ที่มีอยู่จริงใน repo สำหรับงานนี้
- ต้องทำหลัง: T-01, T-02
- เสร็จเมื่อ:
  - ระบุขั้นตอนการส่งกลับเอกสารหรือไม่อนุมัติตาม FR-DOC-03: เมื่อเอกสารไม่ครบถ้วนหรือไม่ถูกต้อง ผู้ตรวจสอบเลือกส่งกลับหรือไม่อนุมัติ ระบบต้องระบุเหตุผลก่อนบันทึกผลดังกล่าว
  - ระบุเงื่อนไขว่าระบบต้องไม่สามารถส่งกลับหรือไม่อนุมัติโดยไม่มีเหตุผล: ตาม AC-DOC-02 เมื่อเอกสารไม่ถูกต้อง การส่งกลับหรือไม่อนุมัติจะต้องมีเหตุผลก่อนบันทึกผลและหากไม่มีเหตุผล ระบบต้องปฏิเสธการบันทึก
  - ระบุให้ชัดเจนว่าไม่มีการกำหนดรูปแบบ ความยาว หรือฟิลด์ของเหตุผลเพิ่มเติม หาก spec.md ไม่ได้ระบุไว้: ต้องระบุเหตุผลประกอบการส่งกลับหรือไม่อนุมัติตาม FR-DOC-03 และ Constraints โดยไม่กำหนดรูปแบบ ความยาว หรือรายละเอียดเพิ่มเติมที่ spec.md ไม่ได้ระบุ
  - ระบุผลลัพธ์เมื่อมีเหตุผลและบันทึกสำเร็จ: ระบบจะบันทึกผลส่งกลับ/ไม่อนุมัติพร้อมเหตุผลตาม FR-DOC-03 และสอดคล้องกับ AC-DOC-02
  - ระบุผลลัพธ์เมื่อไม่มีเหตุผล: ระบบต้องไม่บันทึกผลส่งกลับ/ไม่อนุมัติ และต้องปฏิเสธการดำเนินการตาม AC-DOC-02
  - ตรวจสอบความสอดคล้องกับ FR-DOC-03 และ AC-DOC-02: การไม่อนุมัติหรือส่งกลับเอกสารที่ไม่ถูกต้องต้องมีเหตุผลเป็นเงื่อนไขก่อนการบันทึกผล และ T-04 ต้องไม่ขยาย scope หรือเพิ่มกติกาใหม่ที่ไม่ระบุใน spec.md
  - ใช้เฉพาะข้อมูลที่มีใน spec.md และ T-01/T-02 เท่านั้น ห้ามกำหนดรายละเอียดฟิลด์ การจัดเก็บ หรือรูปแบบเหตุผลเพิ่มเติม และไม่ข้ามไปสู่ T-05/T-06
- สถานะ: Done

### T-05: บันทึกประวัติการตรวจสอบเอกสาร
- รองรับ: NFR-AUD-01
- ตรวจด้วย: -
- ไฟล์ที่แตะ: ไม่มีไฟล์ implementation หรือ test ที่มีอยู่จริงใน repo สำหรับงานนี้
- ต้องทำหลัง: T-03, T-04
- เสร็จเมื่อ:
  - ระบุว่าต้องมีการบันทึกประวัติการตรวจสอบเอกสารตาม NFR-AUD-01: ระบบต้องมีประวัติการตรวจสอบเอกสารเพื่อให้สามารถตรวจสอบย้อนหลังผลการตรวจสอบตามข้อกำหนดที่ระบุใน spec.md
  - ระบุขอบเขตของงานเท่าที่ Specification รองรับ: การบันทึกประวัติต้องครอบคลุมผลการตรวจสอบที่เกิดขึ้นตาม T-03 และ T-04 โดยไม่ขยายข้อกำหนดหรือสร้างโครงสร้างข้อมูลใหม่ที่ spec.md ไม่ได้ระบุไว้
  - กำหนดให้ประวัติสอดคล้องกับผลการตรวจสอบที่เกิดขึ้นจริง: เมื่อมีการอนุมัติหรือส่งกลับ/ไม่อนุมัติ ระบบต้องมีการบันทึกประวัติเพื่อสะท้อนผลการตรวจสอบและเหตุผลที่เกี่ยวข้องตามข้อกำหนดเดิม แต่ไม่กำหนดฟิลด์หรือโครงสร้างข้อมูลเพิ่มเติมที่ spec.md ไม่ได้ระบุชัดเจน
  - ระบุข้อจำกัดให้ชัดเจน: spec.md ไม่มีรายละเอียดเชิงโครงสร้างสำหรับประวัติการตรวจสอบ เช่น ชื่อฟิลด์ รูปแบบข้อมูล วันที่/เวลา การจัดเก็บประวัติ หรือสิทธิ์ในการแก้ไขประวัติ ดังนั้นรายละเอียดเหล่านี้ต้องถือเป็นประเด็นที่ต้องยืนยันกับผู้รับผิดชอบก่อนกำหนดกติกาเพิ่มเติม และห้ามคิดขึ้นเอง
  - ตรวจสอบความสอดคล้องกับ NFR-AUD-01: T-05 ต้องสอดคล้องกับข้อกำหนดว่าบันทึกประวัติการตรวจสอบเอกสารเพื่อให้สามารถตรวจสอบย้อนหลังได้ตามที่ spec ระบุ โดยไม่ขยายออกจากขอบเขตที่มีอยู่
  - ใช้เฉพาะข้อมูลที่มีใน spec.md และงานที่กำหนดไว้ใน T-03/T-04 เท่านั้น ห้ามเพิ่ม Scope หรือ Requirement ใหม่ และไม่ข้ามไปสู่ T-06
- สถานะ: Done

### T-06: ทดสอบ Acceptance Criteria และความต้องการเชิงคุณภาพ
