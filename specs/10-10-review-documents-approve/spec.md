# Feature: ตรวจสอบเอกสารและอนุมัติ
Spec ID: SPEC-10-10- | Source: Use Case Diagram UC-10 | Use case: UC-10
Owner: ทีม A | Status: Draft v2 | Updated: 2569-09-19

## Goal
อาจารย์ตรวจสอบเอกสารของผู้สมัครและบันทึกผลอนุมัติ

## Scope
### In scope
- แสดงเอกสารของผู้สมัครตามสิทธิ์และสามารถตรวจสอบได้ตามรูปแบบที่กำหนด
- ตรวจสอบความครบถ้วน/ถูกต้องตามรายการเอกสารที่ต้องใช้
- อนุมัติหรือส่งกลับพร้อมระบุเหตุผล
- บันทึกผลตรวจสอบและประวัติการตรวจสอบเอกสาร
- จัดการเวอร์ชันเอกสารเมื่อผู้สมัครส่งใหม่หรือแก้ไขเอกสาร
- ตรวจซ้ำเฉพาะเอกสารที่แก้ไขหลังจากผู้สมัครส่งเอกสารใหม่
### Out of scope
- ดูสถานะการสมัคร (UC-03)
- คัดเลือกผู้สมัคร (UC-08)

## Constraints
- เข้าถึงเอกสารได้ตามสิทธิ์
- เมื่อส่งกลับหรือไม่อนุมัติ ต้องระบุเหตุผลก่อนบันทึกผลการตรวจ
- เอกสารที่ผู้สมัครส่งใหม่หรือแก้ไขแล้ว ต้องมีการตรวจใหม่ตามกระบวนการที่กำหนด
- ประวัติการตรวจสอบและเวอร์ชันเอกสารต้องถูกบันทึกเพื่อใช้ตรวจสอบย้อนหลัง

## Requirements
- FR-DOC-01 ระบบต้องแสดงเอกสารของผู้สมัครตามสิทธิ์และให้สามารถตรวจสอบได้ตามรูปแบบที่กำหนด    <- UC-10 requirement 1
- FR-DOC-02 ระบบต้องบันทึกผลตรวจสอบพร้อมประวัติการตรวจสอบและเวอร์ชันเอกสารที่เกี่ยวข้องเมื่อมีการตรวจ    <- UC-10 requirement 2
- FR-DOC-03 เมื่อส่งกลับหรือไม่อนุมัติ ต้องระบุเหตุผลก่อนบันทึกผลการตรวจ    <- UC-10 requirement 3

## Quality Requirements
- NFR-SEC-01 เอกสารต้องเข้าถึงได้เฉพาะผู้มีสิทธิ์ที่ได้รับการยืนยัน
- NFR-AUD-01 บันทึกประวัติการตรวจสอบเอกสารพร้อมข้อมูลที่จำเป็นสำหรับการตรวจสอบย้อนหลัง

## Acceptance Criteria
- [ ] AC-DOC-01 (FR-DOC-02)
      Given เอกสารถูกต้องครบ
            When  อาจารย์อนุมัติ
            Then  ระบบบันทึกผลอนุมัติและบันทึกประวัติการตรวจสอบ
- [ ] AC-DOC-02 (FR-DOC-03)
      Given เอกสารไม่ถูกต้อง
            When  ส่งกลับหรือไม่อนุมัติ
            Then  ระบบบังคับระบุเหตุผลก่อนบันทึกผลการตรวจ
- [ ] AC-DOC-03 (NFR-SEC-01)
      Given ไม่มีสิทธิ์ดูเอกสาร
            When  เปิดเอกสาร
            Then  ระบบปฏิเสธการเข้าถึงและแสดงข้อความที่ชัดเจน

## Assumptions & Open Questions
- ASM-01 ประเภทและรายการเอกสารที่ต้องตรวจสอบถูกกำหนดไว้ในประกาศรับสมัครหรือรายการเอกสารที่ระบุไว้ล่วงหน้า -> Assumption: ยังต้องยืนยันกับผู้รับผิดชอบ
- ASM-02 ผู้มีสิทธิ์เข้าดูและตรวจเอกสารคือผู้ที่เกี่ยวข้องกับกระบวนการรับสมัคร เช่น อาจารย์ผู้รับผิดชอบหรือเจ้าหน้าที่ที่ได้รับมอบหมาย -> Assumption: ยังต้องยืนยันกับผู้รับผิดชอบ
- ASM-03 เมื่อผู้สมัครส่งเอกสารใหม่หรือแก้ไขเอกสาร ระบบอาจตรวจซ้ำเฉพาะรายการที่แก้ไขเท่านั้น -> Assumption: ยังต้องยืนยันกับผู้รับผิดชอบ
- ASM-04 ประวัติการตรวจสอบควรมีข้อมูลอย่างน้อย เช่น ผู้ตรวจ, วันที่เวลา, ผลการตรวจ, เหตุผล, สถานะเอกสาร และเวอร์ชันเอกสาร -> Assumption: ยังต้องยืนยันกับผู้รับผิดชอบ
- ASM-05 ระบบอาจต้องจัดการเวอร์ชันเอกสารเพื่อระบุเวอร์ชันล่าสุดและเวอร์ชันที่ถูกตรวจสอบล่าสุด -> Assumption: ยังต้องยืนยันกับผู้รับผิดชอบ
- Q-01 เอกสารที่แก้ไขแล้วต้องตรวจซ้ำทั้งหมดหรือเฉพาะรายการที่แก้? -> ยืนยันกับผู้รับผิดชอบ
- Q-02 มีผู้มีสิทธิ์เข้าดูเอกสารกี่บทบาท และสิทธิ์เข้าถึงมีข้อจำกัดอย่างไร? -> ยืนยันกับผู้รับผิดชอบ
- Q-03 เมื่อส่งกลับหรือไม่อนุมัติ ต้องใช้รูปแบบเหตุผลแบบข้อความอิสระหรือเลือกจากสาเหตุที่กำหนดไว้? -> ยืนยันกับผู้รับผิดชอบ
- Q-04 ต้องมีการจัดการเวอร์ชันเอกสารสำหรับทุกเอกสารหรือเฉพาะเอกสารบางประเภท? -> ยืนยันกับผู้รับผิดชอบ
- Q-05 เมื่อมีการส่งกลับ ผู้สมัครสามารถส่งเอกสารใหม่ได้ทันทีหรือมีเงื่อนไขเพิ่มเติม? -> ยืนยันกับผู้รับผิดชอบ
- Q-06 หากผลการอนุมัติถูกพบว่าผิดพลาด ต้องสามารถแก้ไขผลการตรวจได้หรือไม่? -> ยืนยันกับผู้รับผิดชอบ
