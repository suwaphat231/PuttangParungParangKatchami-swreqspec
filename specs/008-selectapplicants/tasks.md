- อ้างอิง: [plan.md](./plan.md)

มีทั้งหมด 6 tasks และไม่มี task ที่ต้องรอ Open Questions
งานเรียงจากการตรวจสิทธิ์/สถานะและผลคัดเลือก ไปยังการบันทึก แจ้งผล audit และหน้าจอ

### T-01 ตรวจสอบสิทธิ์และสถานะผู้สมัคร
- รองรับ: FR-SEL-01, NFR-SEC-01
- ตรวจด้วย: AC-SEL-01, AC-SEL-05
- ไฟล์ที่แตะ: `backend/` ตามโครงที่มีอยู่
- ต้องทำหลัง: ไม่มี
- เสร็จเมื่อ: ระบบอนุญาตเฉพาะอาจารย์เจ้าของวิชาและผู้สมัครสถานะอยู่ระหว่างการพิจารณา
- สถานะ: พร้อมทำ

### T-02 กำหนดผลคัดเลือกและยืนยันโดยไม่จำกัดโควตา
- รองรับ: FR-SEL-01, FR-SEL-02
- ตรวจด้วย: AC-SEL-01, AC-SEL-02
- ไฟล์ที่แตะ: `backend/` ตามโครงที่มีอยู่
- ต้องทำหลัง: T-01
- เสร็จเมื่อ: ผลรับได้เฉพาะ `ผ่าน`/`ไม่ผ่าน` และยืนยันได้แม้จำนวนผู้ผ่านมากกว่าจำนวนที่รับ
- สถานะ: พร้อมทำ

### T-03 บันทึกผู้ทำรายการและเวลา
- รองรับ: FR-SEL-03
- ตรวจด้วย: AC-SEL-03
- ไฟล์ที่แตะ: `backend/` ตามโครงที่มีอยู่
- ต้องทำหลัง: T-02
- เสร็จเมื่อ: ทุกผลคัดเลือกที่ยืนยันแล้วบันทึกผู้ทำรายการและเวลาที่บันทึก
- สถานะ: พร้อมทำ

### T-04 แจ้งผลการคัดเลือกผ่านระบบ
- รองรับ: FR-SEL-04
- ตรวจด้วย: AC-SEL-04
- ไฟล์ที่แตะ: `backend/` ตามโครงที่มีอยู่
- ต้องทำหลัง: T-03
- เสร็จเมื่อ: ผู้สมัครได้รับข้อความผล `ผ่าน` หรือ `ไม่ผ่าน` หลังบันทึกผลสำเร็จ
- สถานะ: พร้อมทำ

### T-05 เก็บประวัติรอบและรายชื่อผู้สมัคร
- รองรับ: NFR-AUD-01
- ตรวจด้วย: AC-SEL-06
- ไฟล์ที่แตะ: `backend/` ตามโครงที่มีอยู่
- ต้องทำหลัง: T-03
- เสร็จเมื่อ: เหตุการณ์เปิด/ปิดรอบเก็บรายละเอียดรอบและรายชื่อผู้สมัครในประวัติ และไม่สร้างประวัติจากการแก้ผลคัดเลือก
- สถานะ: พร้อมทำ

### T-06 ทำหน้าจอคัดเลือกและเชื่อมต่อ API
- รองรับ: FR-SEL-01, FR-SEL-02, FR-SEL-04, NFR-SEC-01
- ตรวจด้วย: AC-SEL-01, AC-SEL-02, AC-SEL-04, AC-SEL-05
- ไฟล์ที่แตะ: `frontend/src/App.jsx`, `frontend/src/api/client.js`, `frontend/src/index.css`
- ต้องทำหลัง: T-01, T-02, T-04
- เสร็จเมื่อ: หน้าจอให้อาจารย์เลือกผลได้สองค่า แสดงการปฏิเสธสิทธิ์ และแสดงผลแจ้งผู้สมัครหลังบันทึกสำเร็จ
- สถานะ: พร้อมทำ
