# Implementation Plan: ดูสถานะการสมัคร

Spec: `SPEC-03-03`  
Source: UC-03  
Status: Draft  
Updated: 2569-09-19

## Objective
พัฒนาหน้าสำหรับนักศึกษาที่เข้าสู่ระบบเพื่อดูรายการใบสมัครของตนเอง สถานะล่าสุด เวลาอัปเดต เหตุผล และรายการที่ต้องแก้ไข โดยข้อมูลต้องเป็นข้อมูลล่าสุดและไม่เปิดเผยใบสมัครของผู้อื่น

## Scope
- ตรวจสอบ session ก่อนเข้าถึงข้อมูล
- แสดงใบสมัครของผู้ใช้ปัจจุบันเท่านั้น
- แสดงสถานะล่าสุดจากชุดสถานะมาตรฐาน
- แสดงวันเวลาที่อัปเดตล่าสุดใน `Asia/Bangkok`
- เรียงรายการล่าสุดก่อนและกรองตามประกาศ
- แสดงเหตุผลและรายการที่ต้องแก้เมื่อถูกส่งกลับหรือไม่ผ่าน
- แสดงเฉพาะสถานะปัจจุบัน ไม่แสดงประวัติสถานะ

## Design Decisions
- สถานะที่แสดง ได้แก่ `ยื่นแล้ว`, `รอตรวจสอบ`, `ส่งกลับแก้ไข`, `ผ่าน`, `ไม่ผ่าน` และ `ถอนแล้ว`
- สถานะ `ผ่าน` และ `ไม่ผ่าน` เปลี่ยนโดยอาจารย์เท่านั้น
- โหลดข้อมูลล่าสุดทุกครั้งที่ผู้ใช้เปิดหน้า
- การเรียงลำดับใช้เวลาที่อัปเดตล่าสุดจากระบบ
- การกรองใช้ประกาศที่ผู้ใช้มีใบสมัครอยู่
- ผู้ใช้ไม่มีสิทธิ์เปลี่ยนสถานะจากหน้าดูสถานะ

## Work Plan

### 1. Data Model and Status Rules
- [ ] กำหนด enum/status ของใบสมัครทั้ง 6 สถานะ
- [ ] กำหนดฟิลด์สถานะล่าสุด เวลาอัปเดต เหตุผล และรายการที่ต้องแก้
- [ ] กำหนดความสัมพันธ์ระหว่างใบสมัคร ผู้ใช้ และประกาศ
- [ ] กำหนด transition ที่อนุญาตและป้องกันการย้อนสถานะโดยไม่มีสิทธิ์
- [ ] เก็บเวลาแบบ timezone-aware และแสดงผลใน `Asia/Bangkok`

### 2. Authentication and Data Access
- [ ] ตรวจสอบ session ก่อนเรียกข้อมูล
- [ ] ใช้ user id จาก session เป็นเงื่อนไขหลักในการค้นหาใบสมัคร
- [ ] ป้องกันการรับ user id จาก client มาใช้แทนเจ้าของข้อมูล
- [ ] ตรวจสอบว่า endpoint รายละเอียดใบสมัครตรวจ ownership ซ้ำอีกครั้ง
- [ ] กำหนดการตอบกลับเมื่อไม่ได้เข้าสู่ระบบหรือไม่มีสิทธิ์

### 3. Application Status List
- [ ] สร้าง query/API สำหรับรายการใบสมัครของผู้ใช้ปัจจุบัน
- [ ] เรียงตามเวลาอัปเดตล่าสุดจากมากไปน้อย
- [ ] รองรับการกรองตามประกาศ
- [ ] แสดงประกาศ เลขใบสมัคร สถานะ และเวลาอัปเดตล่าสุด
- [ ] กำหนด empty state เมื่อไม่มีใบสมัครหรือไม่พบผลจากตัวกรอง

### 4. Application Status Detail
- [ ] แสดงสถานะปัจจุบันจากข้อมูลล่าสุด
- [ ] แสดงเวลาอัปเดตล่าสุดในเวลาไทย
- [ ] แสดงเหตุผลและรายการที่ต้องแก้เมื่อสถานะเป็น `ส่งกลับแก้ไข` หรือ `ไม่ผ่าน`
- [ ] ไม่แสดงข้อมูลเหตุผลที่ไม่เกี่ยวข้องกับใบสมัครนั้น
- [ ] ไม่เปิดความสามารถแก้ไขสถานะจากหน้าของนักศึกษา

### 5. Freshness and Reliability
- [ ] โหลดข้อมูลจากแหล่งข้อมูลล่าสุดทุกครั้งที่เปิดหน้า
- [ ] กำหนด loading, empty, error และ unauthorized state
- [ ] ตรวจสอบการจัดการกรณีสถานะถูกอัปเดตระหว่างเปิดรายการกับเปิดรายละเอียด
- [ ] ป้องกัน cache ที่ทำให้แสดงสถานะเก่าโดยไม่แจ้งผู้ใช้
- [ ] บันทึกเหตุการณ์การเข้าดูข้อมูลตามนโยบาย audit ที่เกี่ยวข้อง

## Test Plan

### Functional Tests
- [ ] แสดงรายการใบสมัครของผู้ใช้ปัจจุบัน (AC-STS-01)
- [ ] แสดงสถานะล่าสุดและเวลา `Asia/Bangkok` (AC-STS-02)
- [ ] แสดงเหตุผลและรายการที่ต้องแก้เมื่อส่งกลับหรือไม่ผ่าน (AC-STS-03)
- [ ] รองรับสถานะทั้ง 6 ค่าและแสดงเฉพาะสถานะล่าสุด (AC-STS-04)
- [ ] เรียงล่าสุดก่อนและกรองตามประกาศ (AC-STS-05)
- [ ] เปิดหน้าใหม่แล้วได้ข้อมูลสถานะล่าสุด (AC-STS-06)
- [ ] ผู้ใช้ที่ยังไม่เข้าสู่ระบบเข้าถึงข้อมูลไม่ได้
- [ ] ไม่มีใบสมัครของผู้อื่นปะปนในรายการหรือรายละเอียด

### Security and Reliability Tests
- [ ] ผู้ใช้พยายามเปิดเลขใบสมัครของผู้อื่นแล้วถูกปฏิเสธ (AC-STS-07)
- [ ] สถานะไม่ย้อนกลับโดยไม่มีสิทธิ์ (AC-STS-08)
- [ ] ผู้ใช้ทั่วไปไม่สามารถเปลี่ยนสถานะ `ผ่าน` หรือ `ไม่ผ่าน`
- [ ] เหตุผลและรายการที่ต้องแก้แสดงชัดเจนและอ่านเข้าใจได้ (AC-STS-09)
- [ ] ทดสอบข้อมูลถูกอัปเดตระหว่างการโหลดรายการและรายละเอียด

## Dependencies
- ระบบ authentication/session
- ข้อมูลบัญชีผู้ใช้
- ข้อมูลใบสมัครจาก UC-01
- ข้อมูลประกาศจาก UC-02
- workflow การเปลี่ยนสถานะโดยอาจารย์
- ฐานข้อมูลที่รองรับการค้นหา เรียงลำดับ และ timezone-aware timestamp

## Open Items
- [ ] ยืนยันข้อความเมื่อไม่เข้าสู่ระบบหรือไม่มีสิทธิ์
- [ ] ยืนยันว่ารายการที่ต้องแก้เก็บเป็นข้อความ รายการ หรือทั้งสองรูปแบบ
- [ ] ยืนยันการแสดงเลขใบสมัครและข้อมูลประกาศในรายการ
- [ ] ยืนยันนโยบาย cache และระยะเวลาที่ถือว่าข้อมูลสด
- [ ] ยืนยัน audit log สำหรับการเข้าดูข้อมูลของนักศึกษา
