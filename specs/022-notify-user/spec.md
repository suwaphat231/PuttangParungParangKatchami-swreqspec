# Feature: แจ้งเตือนผู้ใช้งาน
Spec ID: SPEC-22-22- | Source: Use Case Diagram UC-22 | Use case: UC-22
Owner: ทีม A | Status: Draft v1 | Updated: 2569-09-19

## Goal
ผู้ใช้งานได้รับการแจ้งเตือนเกี่ยวกับสถานะหรือเหตุการณ์ที่เกี่ยวข้องกับตนเอง

## Scope
### In scope
- รับรายการแจ้งเตือนจากระบบ
- เลือกช่องทางที่ผู้ใช้อนุญาต
- ส่งข้อความ
- บันทึกสถานะการแจ้งเตือน
### Out of scope
- ดูสถานะการสมัคร (UC-03)
- กระบวนการที่เกี่ยวข้องกับการแจ้งเตือนอื่น ๆ

## Constraints
- ส่งเฉพาะผู้รับที่มีสิทธิ์และมีข้อมูลช่องทาง
- ข้อความต้องไม่เปิดเผยข้อมูลส่วนบุคคลเกินจำเป็น

## Requirements
- FR-MSG-01 ระบบต้องระบุผู้รับและเหตุการณ์ของการแจ้งเตือน พร้อมข้อมูลที่จำเป็นสำหรับการจัดส่ง โดยไม่เปิดเผยข้อมูลที่เกินสิทธิ์    <- UC-22 requirement 1
- FR-MSG-02 ระบบต้องส่งข้อความผ่านช่องทางที่ผู้ใช้ได้เปิดใช้งานและยอมรับการติดต่อ เช่น SMS, LINE, Email หรือ notification ภายในระบบ ตามนโยบายการจัดลำดับช่องทางและเงื่อนไขความพร้อม    <- UC-22 requirement 2
- FR-MSG-03 ระบบต้องบันทึกสถานะการส่งเป็น sent/failed/queued พร้อมเหตุผลและเวลาของการพยายามส่ง    <- UC-22 requirement 3

## Quality Requirements
- NFR-REL-02 การแจ้งเตือนที่ล้มเหลวต้องถูก retry ตามนโยบายและมีการบันทึกสถานะเพื่อติดตาม
- NFR-SEC-01 เนื้อหาการแจ้งเตือนต้องไม่เปิดเผยข้อมูลอ่อนไหวเกินจำเป็น และต้องใช้ข้อมูลเฉพาะที่จำเป็นต่อการติดต่อหรืออธิบายเหตุการณ์

## Acceptance Criteria
- [ ] AC-MSG-01 (FR-MSG-01)
      Given ผู้ใช้มีข้อมูลช่องทางการติดต่อที่ถูกต้องและมีเหตุการณ์ที่ต้องแจ้งเตือน
            When  ระบบสร้างข้อความแจ้งเตือน
            Then  ระบบระบุผู้รับ เหตุการณ์ และ metadata ที่จำเป็น โดยไม่เปิดเผยข้อมูลเกินสิทธิ์
- [ ] AC-MSG-02 (FR-MSG-02)
      Given ผู้ใช้เปิดใช้งานช่องทางที่รองรับและมีข้อมูลที่พร้อมใช้งาน
            When  ระบบส่งแจ้งเตือน
            Then  ระบบเลือกช่องทางที่อนุญาตและส่งข้อความสำเร็จผ่านช่องทางนั้น
- [ ] AC-MSG-03 (FR-MSG-03, NFR-REL-02)
      Given ช่องทางส่งไม่พร้อมหรือการส่งล้มเหลว
            When  ระบบพยายามส่งแจ้งเตือน
            Then  ระบบบันทึกสถานะ failed/queued ตามนโยบาย และดำเนินการ retry ตามเงื่อนไขที่กำหนด
- [ ] AC-MSG-04 (NFR-SEC-01)
      Given ข้อความมีข้อมูลผู้สมัครหรือข้อมูลส่วนบุคคล
            When  ส่งแจ้งเตือน
            Then  ข้อความไม่เปิดเผยข้อมูลอ่อนไหวเกินความจำเป็นและเป็นไปตามนโยบายความปลอดภัย

## Assumptions & Open Questions
- ASM-01 ระบบแจ้งเตือนรองรับ notification ภายในระบบเท่านั้น
- ASM-02 ช่องทางที่ใช้ส่งต้องเป็นช่องทางที่ผู้ใช้เปิดใช้งานและมีข้อมูลติดต่อที่ถูกต้องตามนโยบายความปลอดภัย
- ASM-03 หากผู้ใช้ไม่มีช่องทางที่พร้อมใช้งาน ระบบจะไม่ส่งข้อความและบันทึกสถานะ failed/queued พร้อมเหตุผล
- Q-01 ช่องทางใดบ้างที่ระบบต้องรองรับสำหรับการแจ้งเตือน? -> ตอบ: notification ในระบบเท่านั้น
