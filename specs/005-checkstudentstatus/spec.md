# Feature: ตรวจสอบสถานะนักศึกษา
Spec ID: SPEC-05-05- | Source: Use Case Diagram UC-05 | Use case: UC-05
Owner: ทีม A | Status: Clarified v1.1 | Updated: 2569-09-19

## Goal
ระบบตรวจสอบสถานะการเป็นนักศึกษาของผู้ใช้งานเพื่อยืนยันว่าผู้มีสิทธิ์หรือผู้ที่ผ่านเงื่อนไขสามารถดำเนินการต่อไปได้ก่อนการทำธุรกรรมที่ต้องใช้ผลตรวจสอบ

## Scope
### In scope
- รับข้อมูลประจำตัวนักศึกษาจากผู้ใช้หรือระบบที่เกี่ยวข้อง
- ส่งรหัสประจำตัวนักศึกษาต่อระบบทะเบียนเพื่อค้นหาสถานะ
- รับผลสถานะจากระบบทะเบียนและกำหนดผลต่อการอนุมัติธุรกรรม
- บันทึกข้อมูลที่จำเป็นต่อธุรกรรม เช่น รหัสนักศึกษา ผลตรวจสอบ วันที่และเวลา และแหล่งข้อมูล
### Out of scope
- การสมัครเป็น Lab Boy (UC-01)
- การคัดเลือกผู้สมัคร (UC-08)
- การแก้ไขข้อมูลภายในระบบทะเบียน

## Constraints
- ต้องใช้ข้อมูลจากระบบทะเบียนที่เชื่อถือได้ และใช้เกณฑ์จากแหล่งข้อมูลที่เป็นทางการ
- ต้องไม่เก็บข้อมูลส่วนบุคคลเกินความจำเป็น
- หากระบบทะเบียนไม่ตอบสนอง ส่งค่า error หรือคืนข้อมูลไม่สมบูรณ์ ระบบต้องถือว่าผลตรวจสอบเป็นไม่ผ่าน

## Requirements
- FR-REG-01 ระบบต้องส่งรหัสประจำตัวนักศึกษา (Student ID) และข้อมูลจำเพาะที่จำเป็นไปยังระบบทะเบียนเพื่อค้นหาสถานะ    <- UC-05 requirement 1
- FR-REG-02 ระบบต้องรับผลสถานะนักศึกษาจากระบบทะเบียนอย่างชัดเจน เช่น Active, Inactive, Suspended, Not Found, หรือ Unknown    <- UC-05 requirement 2
- FR-REG-03 หากระบบทะเบียนไม่ตอบสนอง ส่งค่า error หรือผลตรวจสอบไม่ครบถ้วน ระบบต้องไม่ถือว่าเป็นสถานะผ่าน และต้องปฏิเสธธุรกรรมที่ต้องใช้ผลตรวจสอบ    <- UC-05 requirement 3
- FR-REG-04 ระบบต้องบันทึกผลตรวจสอบที่จำเป็นต่อธุรกรรม ได้แก่ รหัสนักศึกษา, วันที่และเวลา, ผลสถานะ, และแหล่งข้อมูล

## Quality Requirements
- NFR-SEC-01 การแลกเปลี่ยนข้อมูลระหว่างระบบต้องเข้ารหัส
- NFR-REL-01 หากระบบทะเบียนล่มหรือไม่ตอบสนอง ต้องไม่สร้างผลตรวจสอบผ่านโดยอัตโนมัติ
- NFR-INT-01 ระบบต้องสื่อสารกับระบบทะเบียนตามรูปแบบข้อมูลและรหัสสถานะที่ตกลงร่วมกัน

## Acceptance Criteria
- [ ] AC-REG-01 (FR-REG-01, FR-REG-02)
      Given ระบบทะเบียนพร้อมใช้งานและมีข้อมูลนักศึกษาอยู่
            When  ระบบส่งรหัสประจำตัวนักศึกษาเพื่อสอบถามสถานะ
            Then  ระบบได้รับผลสถานะที่ชัดเจนจากระบบทะเบียนและสามารถระบุความถูกต้องของสถานะนักศึกษานั้นได้
- [ ] AC-REG-02 (FR-REG-03)
      Given ระบบทะเบียนไม่ตอบสนองหรือส่งผลไม่สมบูรณ์
            When  ระบบตรวจสอบสถานะนักศึกษา
            Then  ธุรกรรมที่ต้องใช้ผลตรวจสอบไม่ถูกอนุมัติ และระบบรายงานผลเป็น "ไม่ผ่าน" หรือ "ไม่สามารถตรวจสอบได้"
- [ ] AC-REG-03 (FR-REG-02, FR-REG-03)
      Given ระบบทะเบียนคืนสถานะ "Inactive", "Suspended", หรือ "Not Found"
            When  ระบบประมวลผลผลตรวจสอบ
            Then  ระบบไม่ถือว่าเป็นสถานะผ่าน และจะปฏิเสธการดำเนินการที่ต้องใช้สถานะนักศึกษา

## Assumptions & Open Questions
- ASM-01 มี API/ช่องทางเชื่อมต่อระบบทะเบียนที่ให้บริการตรวจสอบสถานะนักศึกษา
- ASM-02 รหัสประจำตัวนักศึกษา (Student ID) เป็น key หลักในการค้นหาข้อมูล และเป็นข้อมูลที่ตรงกับระบบทะเบียน
- Q-01 ต้องกำหนดค่า status ที่ใช้ร่วมกันระหว่างระบบและระบบทะเบียนอย่างเป็นทางการหรือไม่? -> ได้กำหนดเป็นทางการแล้ว: Active, Inactive, Suspended, Not Found, Unknown
