# Feature: ตรวจสอบสถานะนักศึกษา
Spec ID: SPEC-05-05- | Source: Use Case Diagram UC-05 | Use case: UC-05
Owner: ทีม A | Status: Clarified v2 | Updated: 2569-09-19

## Goal
ระบบตรวจสอบว่านักศึกษามีสถานะตามเงื่อนไขที่กำหนดก่อนดำเนินการที่เกี่ยวข้อง

## Scope
### In scope
- ส่งรหัสนักศึกษาไปยังแหล่งข้อมูลทะเบียน
- รับสถานะนักศึกษา
- บันทึกผลที่จำเป็นต่อธุรกรรม
### Out of scope
- การสมัครเป็น Lab Boy (UC-01)
- การคัดเลือกผู้สมัคร (UC-08)

## Constraints
- ต้องใช้ข้อมูลจากระบบทะเบียนที่เชื่อถือได้
- ไม่ควรเก็บข้อมูลส่วนบุคคลเกินความจำเป็น

## Requirements
- FR-REG-01 ระบบต้องส่งรหัสนักศึกษาและชื่อเพื่อค้นหาสถานะกับระบบทะเบียน โดยใช้บัญชีอีเมลมหาวิทยาลัยเป็นช่องทางระบุตัวตน    <- UC-05 requirement 1
- FR-REG-02 ระบบต้องรับผลสถานะจากระบบทะเบียนและแปลผลตามสถานะที่ระบบกำหนด โดยถือว่าเฉพาะสถานะ “ปกติ” เท่านั้นที่ผ่าน    <- UC-05 requirement 2
- FR-REG-03 หากตรวจสอบไม่ได้ ได้ข้อมูลไม่ครบ ไม่พบข้อมูล หรือได้รับสถานะผิดปกติ ระบบต้องไม่ถือว่าเป็นสถานะผ่าน และต้องไม่อนุญาตให้ดำเนินธุรกรรมต่อ    <- UC-05 requirement 3
- FR-REG-04 ระบบต้องบันทึกรหัสนักศึกษา ชื่อนักศึกษา และสถานะของนักศึกษาเป็นข้อมูลที่จำเป็นต่อธุรกรรม

## Quality Requirements
- NFR-SEC-01 การแลกเปลี่ยนข้อมูลต้องเข้ารหัส
- NFR-REL-01 หากระบบทะเบียนล่มต้องไม่สร้างข้อมูลผ่านโดยอัตโนมัติ
- NFR-UX-01 เมื่อไม่พบข้อมูลหรือข้อมูลไม่ครบ ระบบต้องแสดงข้อผิดพลาด 404 และให้ผู้ใช้กดรีเฟรชเพื่อลองตรวจสอบใหม่ได้

## Acceptance Criteria
- [ ] AC-REG-01 (FR-REG-01, FR-REG-02)
      Given ระบบทะเบียนพร้อมใช้งาน
            When  ส่งรหัสนักศึกษาและชื่อนักศึกษาผ่านอีเมลมหาวิทยาลัย
            Then  ได้รับสถานะกลับมา
- [ ] AC-REG-02 (FR-REG-02)
      Given ระบบทะเบียนส่งสถานะนักศึกษาเป็น “ปกติ”
            When  ระบบแปลผลสถานะ
            Then  ผลการตรวจสอบเป็นผ่าน
- [ ] AC-REG-03 (FR-REG-03)
      Given ระบบทะเบียนไม่ตอบสนอง
            When  ตรวจสอบสถานะ
            Then  ธุรกรรมที่ต้องใช้ผลตรวจสอบไม่ถูกอนุมัติ
- [ ] AC-REG-04 (FR-REG-03, NFR-UX-01)
      Given ระบบทะเบียนไม่พบข้อมูล หรือส่งข้อมูลไม่ครบ หรือส่งสถานะผิดปกติ
            When  ตรวจสอบสถานะ
            Then  ระบบแสดงข้อผิดพลาด 404 และไม่อนุญาตให้ดำเนินธุรกรรมต่อ
                  And ผู้ใช้สามารถกดรีเฟรชเพื่อลองตรวจสอบใหม่ได้
- [ ] AC-REG-05 (FR-REG-04)
      Given ระบบทะเบียนส่งข้อมูลนักศึกษา
            When  บันทึกผลการตรวจสอบ
            Then  ระบบบันทึกรหัสนักศึกษา ชื่อนักศึกษา และสถานะของนักศึกษา
- [ ] AC-REG-06 (FR-REG-03)
      Given ข้อมูลการสมัครไม่ครบ
            When  ผู้ใช้ตรวจสอบหน้าสมัคร
            Then  ระบบไม่แสดงข้อมูลการสมัคร และไม่อนุญาตให้กดสมัคร

## Assumptions & Open Questions
- ASM-01 มี API/ช่องทางเชื่อมต่อระบบทะเบียน
- Q-01 ใช้รหัสนักศึกษาร่วมกับชื่อเป็นข้อมูลค้นหา โดยใช้อีเมลมหาวิทยาลัยเป็นช่องทางระบุตัวตน
- Q-02 ต้องเก็บผลการตรวจสอบไว้นานเท่าใด และสามารถนำผลเดิมกลับมาใช้ซ้ำได้หรือไม่? -> รอยืนยัน
- Q-03 ผู้ใดหรือธุรกรรมใดมีสิทธิ์เรียกใช้การตรวจสอบสถานะ? -> รอยืนยัน
