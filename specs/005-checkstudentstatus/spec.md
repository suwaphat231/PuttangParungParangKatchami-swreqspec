# Feature: ตรวจสอบสถานะนักศึกษา
Spec ID: SPEC-05-05- | Source: Use Case Diagram UC-05 | Use case: UC-05
Owner: ทีม A | Status: Clarified v2 | Updated: 2569-09-19

## Goal
ระบบตรวจสอบว่านักศึกษามีสถานะตามเงื่อนไขที่กำหนดก่อนดำเนินการที่เกี่ยวข้อง

## Scope
### In scope
- ส่งรหัสนักศึกษาไปยังแหล่งข้อมูลทะเบียน
- รับสถานะนักศึกษา
- บันทึกผลที่จำเป็นต่อธุรกรรม
### Out of scope
- การสมัครเป็น Lab Boy (UC-01)
- การคัดเลือกผู้สมัคร (UC-08)

## Constraints
- ต้องใช้ข้อมูลจากระบบทะเบียนที่เชื่อถือได้
- ไม่ควรเก็บข้อมูลส่วนบุคคลเกินความจำเป็น

## Requirements
- FR-REG-01 ระบบต้องส่งข้อมูลระบุนักศึกษาเพื่อค้นสถานะ    <- UC-05 requirement 1
- FR-REG-02 ระบบต้องรับผลสถานะจากระบบทะเบียนและแปลผลตามสถานะที่ระบบกำหนด โดยถือว่าเฉพาะสถานะที่ระบุว่าเป็นนักศึกษาปัจจุบันเท่านั้นที่ผ่าน    <- UC-05 requirement 2
- FR-REG-03 หากตรวจสอบไม่ได้หรือได้รับสถานะที่ไม่เข้าเกณฑ์ ระบบต้องไม่ถือว่าเป็นสถานะผ่าน และต้องส่งผลไม่ผ่านกลับไปยังธุรกรรมที่เรียกใช้    <- UC-05 requirement 3

## Quality Requirements
- NFR-SEC-01 การแลกเปลี่ยนข้อมูลต้องเข้ารหัส
- NFR-REL-01 หากระบบทะเบียนล่มต้องไม่สร้างข้อมูลผ่านโดยอัตโนมัติ

## Acceptance Criteria
- [ ] AC-REG-01 (FR-REG-02)
      Given ระบบทะเบียนพร้อมใช้งาน
            When  ส่งข้อมูลนักศึกษา
            Then  ได้รับสถานะกลับมา
- [ ] AC-REG-02 (FR-REG-02)
      Given ระบบทะเบียนส่งสถานะนักศึกษาปัจจุบัน
            When  ระบบแปลผลสถานะ
            Then  ผลการตรวจสอบเป็นผ่าน
- [ ] AC-REG-03 (FR-REG-03)
      Given ระบบทะเบียนไม่ตอบสนอง
            When  ตรวจสอบสถานะ
            Then  ธุรกรรมที่ต้องใช้ผลตรวจสอบไม่ถูกอนุมัติ

## Assumptions & Open Questions
- ASM-01 มี API/ช่องทางเชื่อมต่อระบบทะเบียน
- Q-01 ใช้รหัสใดเป็น key หลักในการค้นข้อมูล? -> ยืนยันกับระบบทะเบียน
