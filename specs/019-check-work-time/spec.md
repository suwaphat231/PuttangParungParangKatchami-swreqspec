# Feature: ตรวจสอบวันและเวลาปฏิบัติงาน
Spec ID: SPEC-19-19- | Source: Use Case Diagram UC-19 | Use case: UC-19
Owner: ทีม A | Status: Draft v2 | Updated: 2569-09-19

## Goal
ระบบตรวจสอบว่าการกำหนดวันและเวลาปฏิบัติงานของผู้ปฏิบัติงานหรือระบบจัดตารางไม่ขัดแย้งกับปฏิทินการศึกษาของสถาบัน เช่น วันหยุด วันปิดการเรียน ช่วงเวลาที่ไม่อนุญาตให้ปฏิบัติงาน และวันหยุดพิเศษ เพื่อป้องกันการจัดตารางที่ไม่สอดคล้องกับข้อกำหนดทางการศึกษา

## Scope
### In scope
- รับข้อมูลวันและเวลาที่ต้องการตรวจสอบจาก UC-09
- ดึงข้อมูลปฏิทินการศึกษาและวันหยุดที่มีผลบังคับใช้ในระบบ
- เปรียบเทียบช่วงเวลาที่ขอปฏิบัติงานกับช่วงเวลาที่ไม่อนุญาต
- ส่งผลการตรวจสอบเป็นผ่าน/ไม่ผ่านพร้อมเหตุผลกลับไปยัง UC-09
- ระบุข้อมูลเวอร์ชันหรือวันที่อัปเดตของปฏิทินที่ใช้ในการตรวจสอบ
### Out of scope
- จัดทำตารางปฏิบัติงาน (UC-09)
- กำหนดนโยบายปฏิทินการศึกษาใหม่หรือแก้ไขปฏิทิน (UC-17)

## Constraints
- ปฏิทินการศึกษาที่ใช้ในการตรวจสอบต้องเป็นข้อมูลที่ระบบยอมรับและมีความสดใหม่ตามข้อกำหนด
- หากระบบไม่สามารถเรียกข้อมูลปฏิทินหรือข้อมูลไม่ครบถ้วน ไม่ว่าจะเป็นข้อมูลล้าสมัย หรือข้อมูลไม่พร้อมใช้งาน ต้องไม่ถือว่าผ่าน
- การตรวจสอบต้องพิจารณาว่าช่วงเวลาที่ขอมีการทับซ้อนกับช่วงเวลาที่ห้ามปฏิบัติงานหรือไม่
- ผลลัพธ์ของการตรวจสอบต้องมีสถานะเป็น Pass หรือ Fail และมีเหตุผลที่ชัดเจน

## Requirements
- FR-CAL-01 ระบบต้องรับข้อมูลวันและเวลาที่ต้องการตรวจสอบจาก UC-09 รวมถึงวันเริ่มต้น วันสิ้นสุด และช่วงเวลาปฏิบัติงานที่ต้องการจัดตาราง    <- UC-19 requirement 1
- FR-CAL-02 ระบบต้องเรียกข้อมูลปฏิทินการศึกษาและข้อมูลวันหยุดที่มีผลบังคับใช้จากแหล่งข้อมูลที่ยอมรับได้ของระบบก่อนทำการตรวจสอบ    <- UC-19 requirement 2
- FR-CAL-03 ระบบต้องตรวจสอบว่าช่วงเวลาที่ร้องขออยู่ในช่วงที่อนุญาตหรือมีการทับซ้อนกับวันหยุด/ช่วงเวลาที่ไม่อนุญาต เช่น วันหยุดนักศึกษา วันหยุดราชการ ช่วงปิดภาค/สอบ หรือช่วงที่ห้ามปฏิบัติงาน    <- UC-19 requirement 2
- FR-CAL-04 ระบบต้องปฏิเสธการตรวจสอบและส่งผลเป็นไม่ผ่านเมื่อข้อมูลปฏิทินไม่พร้อมใช้งาน ข้อมูลล้าสมัย หรือไม่สามารถยืนยันความถูกต้องได้    <- UC-19 requirement 2
- FR-CAL-05 ระบบต้องส่งผลการตรวจสอบกลับไปยัง UC-09 เป็นผลผ่านหรือไม่ผ่านพร้อมเหตุผลและข้อมูลอ้างอิงปฏิทินที่ใช้ในการพิจารณา    <- UC-19 requirement 3

## Quality Requirements
- NFR-REL-01 ห้ามใช้ข้อมูลปฏิทินที่ไม่ทราบความสดใหม่หรือไม่เป็นข้อมูลที่ยอมรับได้เพื่อให้ผลการตรวจสอบเป็นผ่าน
- NFR-PERF-01 ระบบต้องตอบสนองผลการตรวจสอบภายในเวลาที่กำหนดและไม่ชักช้าจนเกินเกณฑ์ของธุรกิจ
- NFR-INT-01 ผลการตรวจสอบต้องมีรูปแบบตอบกลับที่ชัดเจนและสอดคล้องกับ UC-09 เช่น status, reason, calendarVersion

## Acceptance Criteria
- [ ] AC-CAL-01 (FR-CAL-01)
      Given ผู้ใช้หรือระบบ UC-09 ต้องการตรวจสอบช่วงเวลาปฏิบัติงาน
            When  ระบบรับข้อมูลวันเริ่มต้นและวันสิ้นสุดของช่วงเวลาที่ต้องการตรวจสอบ
            Then  ระบบต้องบันทึกหรือประมวลผลข้อมูลดังกล่าวเพื่อใช้ในการตรวจสอบต่อไป
- [ ] AC-CAL-02 (FR-CAL-02, FR-CAL-03)
      Given มีข้อมูลปฏิทินการศึกษาที่ใช้งานได้
            When  ระบบตรวจสอบช่วงเวลาที่ร้องขอและช่วงเวลานั้นทับซ้อนกับวันหยุดหรือช่วงที่ไม่อนุญาต
            Then  ระบบต้องระบุผลเป็นไม่ผ่านและแสดงเหตุผลว่ามีการทับซ้อนกับวันหยุดหรือช่วงที่ไม่ได้รับอนุญาต
- [ ] AC-CAL-03 (FR-CAL-04)
      Given ระบบไม่สามารถเรียกข้อมูลปฏิทินการศึกษาได้ หรือข้อมูลไม่เป็นปัจจุบัน
            When  ทำการตรวจสอบช่วงเวลาปฏิบัติงาน
            Then  ระบบต้องส่งผลเป็นไม่ผ่านและไม่อนุญาตให้ถือว่าเป็นผลผ่าน
- [ ] AC-CAL-04 (FR-CAL-03, FR-CAL-05)
      Given ช่วงเวลาที่ร้องขออยู่ภายในช่วงที่อนุญาตตามปฏิทินการศึกษา
            When  ระบบทำการตรวจสอบ
            Then  ระบบต้องส่งผลผ่านกลับไปยัง UC-09 พร้อมเหตุผลที่ระบุว่าเป็นช่วงที่อนุญาตและข้อมูลปฏิทินที่ใช้
- [ ] AC-CAL-05 (FR-CAL-05, NFR-INT-01)
      Given การตรวจสอบเสร็จสิ้น
            When  ระบบตอบกลับไปยัง UC-09
            Then  ผลลัพธ์ต้องมีสถานะ status, เหตุผล reason และข้อมูลอ้างอิงปฏิทิน เช่น calendarVersion หรือ effectiveDate อย่างชัดเจน

## Assumptions & Open Questions
- ASM-01 ระบบปฏิทินการศึกษามี API หรือแหล่งข้อมูลที่ระบบสามารถเรียกใช้ได้และเปิดให้ใช้งาน
- ASM-02 วันหยุดหรือช่วงเวลาที่ไม่อนุญาตหมายถึงช่วงที่สถาบันกำหนดไว้ในปฏิทินการศึกษา เช่น วันหยุดนักศึกษา วันหยุดราชการ ช่วงปิดภาคหรือช่วงสอบที่ห้ามจัดตาราง
- Q-01 กำหนดช่วงเวลาที่ไม่อนุญาตมีความละเอียดเท่าใด เช่น วันเต็มหรือชั่วโมงเฉพาะเวลา? -> ตอบ: ใช้ระดับวันเต็ม (full-day) สำหรับวันหยุดและช่วงที่ไม่อนุญาตที่กำหนดในปฏิทินการศึกษา
- Q-02 หากช่วงเวลาที่ร้องขอมีการทับซ้อนเพียงบางส่วนของวันหรือเวลา จะถือว่าไม่ผ่านทั้งช่วงหรือไม่? -> ตอบ: ถ้ามีการทับซ้อนกันแม้เพียงส่วนใดส่วนหนึ่งของช่วงเวลาที่ร้องขอ ระบบจะถือว่าไม่ผ่านทั้งช่วง
- Q-03 ระบบต้องส่งผลการตรวจสอบกลับไปยัง UC-09 ในรูปแบบใด เช่น JSON, event payload หรือ response object? -> ตอบ: ส่งเป็น JSON
- Q-04 วันหยุดพิเศษที่ประกาศภายหลังอัปเดตเข้าสู่ระบบภายในกี่นาทีจึงถือว่าปัจจุบัน? -> ตอบ: เมื่อมีการอัปเดทข้อมูลแล้ว ถือว่าปัจจุบันทันที และระบบจะใช้ข้อมูลใหม่นั้นได้เลย
