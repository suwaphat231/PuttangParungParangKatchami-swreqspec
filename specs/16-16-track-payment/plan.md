# Implementation Plan: UC-16 ติดตามและตรวจสอบการจ่ายเงิน
Spec Target: [specs/16-16-track-payment/spec.md](specs/16-16-track-payment/spec.md) (v1)

## 1. การรองรับเงื่อนไขใน Spec (Constraints & Scope)
- **การเข้าถึงข้อมูลทางการเงิน (NFR-SEC-01 / RBAC 4 บทบาท):**
  - **นักศึกษา (Lab Boy):** เข้าถึงและดูเฉพาะสถานะและประวัติการรับเงินของตนเองเท่านั้น
  - **อาจารย์ผู้สอน:** ดูสถานะการจ่ายเงินของ Lab Boy เฉพาะในรายวิชาที่ตนเองรับผิดชอบ
  - **เจ้าหน้าที่ภาควิชา:** ติดตามและตรวจสอบการจ่ายเงินของ Lab Boy ทั้งหมดภายในภาควิชาตนเอง
  - **ผู้ดูแลระบบ (Admin):** เข้าถึงและสลับดูข้อมูลการจ่ายเงินได้ทุกภาควิชา
- **ข้อมูลต้นทางไม่ถูกแก้ไข (Constraint / Read-Only):** หน้าระบบใช้เพื่อดูสถานะและตรวจสอบเท่านั้น ไม่รองรับการแก้ไขยอดเงินหรือเปลี่ยนสถานะการจ่ายเงินตรงผ่านหน้านี้
- **การใช้งานข้อมูลจากระบบการเงิน (ASM-01):** เชื่อมโยงข้อมูลสถานะการจ่ายเงินจริงจากระบบการเงินหลัก (Financial System)
- **การระบุรายการที่ต้องดำเนินการต่อ (FR-PAY-03):** รายการที่ยังไม่จ่ายหรือมีความผิดปกติ (`ยังไม่จ่าย` / `ข้อมูลผิดปกติ`) ต้องถูกทำเครื่องหมาย (Flag) ชัดเจน

## 2. ขั้นตอนการพัฒนา (Implementation Tasks)
- [ ] **ส่วนประมวลผลข้อมูล (Backend):**
  - พัฒนา API ดึงข้อมูลรายการจ่ายเงินและดึงสถานะล่าสุดจากระบบการเงิน (Read-only integration)
  - คำนวณและ Mapping สถานะให้อยู่ในกลุ่มมาตรฐาน (`จ่ายแล้ว`, `ยังไม่จ่าย`, `ข้อมูลผิดปกติ`)
  - บังคับใช้ Data Scope กรองข้อมูลตาม RBAC 4 บทบาทของผู้ใช้งาน
  - บันทึก Immutable Audit Log เมื่อมีการเข้าถึงหรือสืบค้นข้อมูลการเงิน
- [ ] **ส่วนหน้าจอผู้ใช้งาน (Frontend):**
  - หน้าแสดงรายการจ่ายเงินพร้อมตัวกรอง (รหัสนักศึกษา, รายวิชา, ภาคการศึกษา, สถานะการจ่าย)
  - UI Tag/Badge ทำเครื่องหมายเน้นรายการ `ยังไม่จ่าย` หรือ `ข้อมูลผิดปกติ` ให้เห็นชัดเจน
  - ล็อคหน้าจอให้อยู่ในรูปแบบ Read-Only โดยไม่มีปุ่ม/ช่องให้แก้ไขข้อมูลต้นทาง

## 3. รายการตรวจสอบ (Acceptance Criteria Checklist)
- [ ] **AC-PAY-01:** แสดงสถานะการจ่ายเงินล่าสุดจากระบบการเงินได้อย่างถูกต้องตามสิทธิ์ของผู้ใช้งาน (4 Roles)
- [ ] **AC-PAY-02:** แสดงเครื่องหมาย (Flag) เตือนรายการที่ยังไม่จ่ายหรือมีความผิดปกติอย่างชัดเจน
- [ ] **AC-PAY-03:** ค้นหาและกรองรายการจ่ายเงินตามรหัสนักศึกษา รายวิชา หรือสถานะได้อย่างถูกต้อง
- [ ] **AC-PAY-04:** ระบบป้องกันการแก้ไขข้อมูลทางการเงิน (Read-only) และบันทึก Audit Log ทุกครั้งที่มีการเรียกดูข้อมูล

## 4. วัตถุประสงค์ของแผน
- ให้การพัฒนาและการทดสอบสอดคล้องกับ UC-16
- ลดความคลุมเครือเรื่องขอบเขตการดูข้อมูลการเงิน และการระบุรายการที่ต้องดำเนินการต่อ
- สร้าง traceability ที่สามารถตรวจสอบได้จาก requirement → implementation → test
