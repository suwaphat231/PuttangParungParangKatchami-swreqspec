# Feature: ติดตามและตรวจสอบการจ่ายเงิน
Spec ID: SPEC-16-16- | Source: Use Case Diagram UC-16 | Use case: UC-16
Owner: ทีม A | Status: Draft v1 | Updated: 2569-09-19

## Goal
เจ้าหน้าที่สามารถติดตามและตรวจสอบสถานะการจ่ายเงินของ Lab Boy จากข้อมูลการปฏิบัติงานและข้อมูลล่าสุดจากระบบการเงิน เพื่อระบุรายการที่ยังไม่ได้รับชำระหรือมีความผิดปกติ

## Scope
### In scope
- ค้นหาผู้ปฏิบัติงานหรือรายการที่เกี่ยวข้อง
- ดูยอด/รายการจ่ายเงินที่เกี่ยวข้อง
- ดึงและแสดงสถานะการจ่ายเงินล่าสุดจากระบบการเงิน
- ระบุรายการที่ยังไม่จ่ายหรือมีความผิดปกติให้ดำเนินการต่อ
- กรองข้อมูลตามสิทธิ์และบทบาทของผู้ใช้งาน
### Out of scope
- ดำเนินการจ่ายเงินเอง (UC-21)

## Constraints
- ข้อมูลการเงินเข้าถึงได้เฉพาะผู้มีสิทธิ์ตามบทบาทและสิทธิ์ของผู้ใช้งาน
- HR และ Manager/Executive ดูข้อมูลการจ่ายเงินได้แบบ Read-only; Student และผู้ปฏิบัติงานทั่วไปไม่มีสิทธิ์เข้าถึงหน้าติดตามการจ่ายเงิน
- หน้าติดตามและตรวจสอบเป็นแบบ Read-only ไม่อนุญาตให้แก้ไขข้อมูลต้นทางหรือเปลี่ยนสถานะการจ่ายเงินผ่านหน้าจอนี้
- ระบบการเงินเป็นแหล่งข้อมูลสถานะการจ่ายเงินที่ถูกต้องและเป็นแหล่งข้อมูลหลัก
- อนุญาตให้ใช้ Mock Finance Data สำหรับพัฒนาและทดสอบ Backend โดยต้องระบุชัดว่าเป็นข้อมูลจำลองและแยกจากข้อมูลจริง; ห้ามอ้างว่าเชื่อมต่อระบบการเงินจริงแล้ว
- ขอบเขตการพัฒนารอบนี้เป็น Backend API และ Business Logic ไม่พัฒนา Frontend หรือหน้า UI ของ UC-16
- รายการที่ยังไม่จ่ายหรือผิดปกติต้องถูกทำเครื่องหมายชัดเจนเพื่อให้เจ้าหน้าที่ดำเนินการต่อ
- สำหรับการสาธิต UC-16 ให้ตรวจ Bearer Token จาก server-side mapping ใน `PAYMENT_DEMO_AUTH_TOKENS` รูปแบบ JSON ที่จับคู่ token กับ `user_id` และ role; เปิดใช้ได้เฉพาะ `APP_ENV=local` หรือ `APP_ENV=test` และค่าเริ่มต้นต้องปิดแบบ production
- บันทึกการอนุญาต/ปฏิเสธของ UC-16 ลงตาราง Audit Log แยก โดยเก็บผู้ใช้ เวลา resource/item และผลการตรวจสิทธิ์; ห้ามบันทึก bearer token และห้ามรับ role จาก request
- API สำหรับ UC-16 ใช้ `GET /payments` ค้นหา/กรอง, `GET /payments/{payment_id}` อ่านสถานะล่าสุดรายรายการ และ `GET /payments/follow-up` อ่านรายการที่ต้องติดตาม; ทุก endpoint เป็น Read-only

## Requirements
- FR-PAY-01 ระบบต้องแสดงรายการจ่ายเงินที่เกี่ยวข้องกับผู้ปฏิบัติงานที่เลือกได้ตามตัวกรองที่กำหนด; ค้นหา `worker_id` และ `payment_reference` แบบ exact match และ `worker_name` แบบ partial match    <- UC-16 requirement 1
- FR-PAY-02 ระบบต้องแสดงสถานะล่าสุดของรายการจากระบบการเงินให้เจ้าหน้าที่เห็นอย่างถูกต้อง โดยข้อมูลรายการมี `payment_id`, `worker_id`, `worker_name`, `payment_reference`, `amount`, `currency`, `finance_status`, `status_updated_at` และ `last_synced_at`; แสดง `PAID` เป็น `ชำระแล้ว`, `UNPAID` เป็น `ยังไม่ได้จ่าย`, `ABNORMAL` เป็น `มีความผิดปกติ`; สถานะอื่นต้อง map จากค่าจริงโดยรักษาความหมาย และเวลาต้องระบุ timezone จากแหล่งข้อมูลต้นทาง    <- UC-16 requirement 2
- FR-PAY-03 ระบบต้องระบุรายการที่ยังไม่ได้จ่ายหรือมีความผิดปกติ เพื่อให้เจ้าหน้าที่ดำเนินการต่อ    <- UC-16 requirement 3
- FR-PAY-04 ระบบต้องจำกัดการเข้าถึงข้อมูลการเงินตามบทบาทและสิทธิ์ของผู้ใช้งาน    <- NFR-SEC-01
- FR-PAY-05 ระบบต้องบันทึกการเข้าถึงและเรียกดูข้อมูลการเงินเพื่อการตรวจสอบย้อนหลัง โดยบันทึกผู้ใช้งาน วันเวลา รายการที่เข้าถึง และผลการอนุญาตหรือปฏิเสธ    <- NFR-AUD-01

## Quality Requirements
- NFR-SEC-01 จำกัดสิทธิ์การเข้าถึงข้อมูลการเงินตามบทบาทและสิทธิ์ของผู้ใช้งาน
- NFR-AUD-01 บันทึกการเข้าถึงและเรียกดูข้อมูลการเงินเพื่อการตรวจสอบย้อนหลัง

## Acceptance Criteria
- [ ] AC-PAY-01 (FR-PAY-02)
      Given แหล่งข้อมูลการเงินที่กำลังใช้งานมีสถานะล่าสุดของรายการ (Mock Finance Data สำหรับการพัฒนา/ทดสอบต้องระบุว่าเป็นข้อมูลจำลอง)
            When  ผู้ใช้งานที่ได้รับอนุญาตเรียก API อ่านรายการจ่ายเงิน
            Then  API คืนสถานะล่าสุดของรายการจากแหล่งข้อมูลนั้น พร้อมยอดเงิน สกุลเงิน และเวลาที่ระบุ timezone โดยไม่มีการแก้ไขข้อมูลต้นทาง
- [ ] AC-PAY-02 (FR-PAY-03)
      Given มีรายการจากแหล่งข้อมูลที่มีสถานะยังไม่ได้จ่ายหรือผิดปกติ
            When  ผู้ใช้งานที่ได้รับอนุญาตเรียก API อ่านรายการติดตาม
            Then  API ระบุรายการดังกล่าวว่าต้องติดตามต่อ โดยไม่แก้ไขสถานะต้นทาง
- [ ] AC-PAY-03 (FR-PAY-01)
      Given ผู้ใช้งานที่ได้รับอนุญาตค้นหาผู้ปฏิบัติงานหรือรายการ
            When  เรียก API รายการจ่ายเงินพร้อมตัวกรอง
            Then  API คืนรายการที่เกี่ยวข้องตามตัวกรอง โดย `worker_id` และ `payment_reference` เป็น exact match และ `worker_name` เป็น partial match
- [ ] AC-PAY-04 (FR-PAY-04)
      Given ผู้ใช้งานมีบทบาทต่างกัน
            When  เข้าถึงหน้าติดตามและตรวจสอบการจ่ายเงิน
            Then  HR และ Manager/Executive ดูข้อมูลได้แบบ Read-only และ Student กับผู้ปฏิบัติงานทั่วไปถูกปฏิเสธการเข้าถึง
- [ ] AC-PAY-05 (FR-PAY-05)
      Given มีการเข้าถึงหรือเรียกดูข้อมูลการเงิน
            When  เจ้าหน้าที่เปิดหรือค้นหารายการ
            Then  ระบบบันทึกผู้ใช้งาน วันเวลา รายการที่เข้าถึง และผลการอนุญาตหรือปฏิเสธไว้ใน Audit Log

## Assumptions & Open Questions
- ASM-01 ระบบการเงินเป็นแหล่งข้อมูลสถานะการจ่ายเงิน; ปัจจุบัน Backend ยังไม่มี API เชื่อมต่อ จึงใช้ Mock Finance Data ที่ระบุแยกชัดเจนได้เฉพาะพัฒนา/ทดสอบ และยังไม่ถือว่าเชื่อมต่อหรือได้รับข้อมูลจริงจากระบบการเงิน
- Q-01 ควรแสดงยอดเงินพร้อมสถานะการจ่ายหรือไม่? -> แสดงยอดเงินพร้อมสถานะการจ่ายเงิน
