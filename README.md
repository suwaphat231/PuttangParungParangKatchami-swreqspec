 Reflection

1.การตรวจสอบความคืบหน้าของงาน
ได้เรียนรู้ว่าควรตรวจสอบ Task และ Acceptance Criteria ให้ครบถ้วน ไม่ควรสรุปว่าฟีเจอร์เสร็จแล้วจากการทำงานเพียงบางส่วน

2.ความสำคัญของ Traceability
ได้เรียนรู้การเชื่อมโยงข้อกำหนดกับกรณีทดสอบผ่าน RTM เพื่อช่วยตรวจสอบความครบถ้วนของระบบ

3.การจัดการข้อกำหนดที่ไม่ชัดเจน
พบว่าหาก Specification ไม่กำหนดพฤติกรรมที่คาดหวัง ควรบันทึกเป็น TODO และขอความชัดเจน แทนการกำหนดผลลัพธ์ขึ้นเอง

4.การทดสอบการเชื่อมต่อของระบบ
ได้เรียนรู้ว่าการทดสอบ Frontend ให้ผ่านยังไม่เพียงพอ ต้องตรวจสอบการเชื่อมต่อระหว่าง Frontend, API และ Backend ด้วย

5.การบันทึกและติดตามงาน
ได้เรียนรู้ว่าการจัดทำเอกสารและบันทึกความคืบหน้าอย่างต่อเนื่อง ช่วยให้ติดตามปัญหาที่เหลือและวางแผนพัฒนาระบบต่อได้อย่างมีประสิทธิภาพ

AC-06
1.การตรวจสอบความคืบหน้าของงาน
เรียนรู้ว่าต้องเช็ก Task และ AC ให้ครบถ้วนจริง ไม่สรุปว่างานเสร็จเพียงเพราะ Test ผ่านด้วย Mock Data (เช่น T-03 ที่หน้าจอพร้อม แต่ Backend จริงยังไม่มี)

2.ความสำคัญของ Traceability
การใช้ RTM เชื่อมโยง Spec, Code และ Test ช่วยให้เจอจุดขัดแย้งได้ไว เช่น ตรวจเจอคำว่า UTC ในข้อความ Test Case ขัดกับ Asia/Bangkok ใน AC (F-006)

3.การจัดการข้อกำหนดที่ไม่ชัดเจน
หาก Spec ไม่ได้กำหนดพฤติกรรมไว้ (เช่น กรณีไม่มีใบสมัคร) ควรบันทึกเป็น TODO เพื่อขอความชัดเจน แทนการเดาเองหรือใส่ Fallback ลอยๆ (F-004)

4.การทดสอบการเชื่อมต่อของระบบ
การทดสอบแค่ฝั่ง Frontend ผ่านยังไม่พอ ต้องสอบทานการเชื่อมต่อจริงระหว่าง Frontend, API และ Backend เพื่อป้องกันช่องโหว่ในระบบจริง (F-001)

5.การบันทึกและติดตามงาน
การลง Log และ RTM ช่วยให้เห็นประวัติการแก้ไขปัญหา (เช่น F-005, F-006) และติดตามการเปลี่ยนสถานะงานอย่าง TC-STS-06-2 ได้อย่างเป็นระบบ ไม่ตกหล่น
